## Why

当前快速问答、智能推理、智能体和 Integration RAG 分别从平台、租户、智能体或接口参数读取检索配置，同名参数语义不一致，导致平台无法预测实际召回预算与最终结果数。需要将检索策略收敛为平台管理员维护的单一真源，让普通管理员和外部调用方只选择检索范围与查询内容，不再覆盖平台策略。

## What Changes

- 扩充现有 `PlatformSettings.RetrievalConfig`，统一管理查询扩展总开关、融合结果数、向量/关键词总召回预算、RRF 权重、rerank 候选数、最终结果数和阈值；rerank 模型继续由平台默认模型配置统一管理。
- 快速问答、智能推理、普通知识搜索、智能体问答、Integration 单次与批量搜索全部读取同一份平台检索配置。
- 智能体已有检索字段保留用于历史数据反序列化，但运行时不再覆盖平台策略；智能体编辑器隐藏对应入口。
- 租户历史 `RetrievalConfig` 保留用于兼容迁移，但读取时由平台配置覆盖；普通管理员和知识搜索页不再显示或写入检索配置。
- Integration `top_k` 保留为调用方可选的响应缩小值，实际返回上限为 `min(top_k, 平台 RerankTopK)`；它不得放大平台最终结果上限，也不得改变召回、融合或 rerank 候选预算。
- Integration 批量搜索增加平台统一维护的整批结果数和正文字符预算；批内按稳定证据身份去重并公平分配预算，防止查询数量放大响应体，同时不新增重复的“批量单条 rerank 数量”配置。
- 平台设置增加仅平台管理员可见、可写的“检索策略”入口；普通管理员只能读取实际生效策略的非敏感摘要，不能修改。
- 启动或迁移时把缺失的平台字段补为当前有效默认值，不从任意单个租户或智能体配置反向推断，避免历史局部配置意外升级为全平台策略。

## Capabilities

### New Capabilities

- `platform-retrieval-settings`: 定义平台检索策略的单一真源、权限、字段语义、消费者一致性和旧配置兼容行为。

### Modified Capabilities

- `integration-knowledge-api`: Integration 单次与批量 RAG 使用平台检索策略，调用方参数不得覆盖召回、融合和 rerank 预算。

## Impact

- 后端：`PlatformSettings` / `RetrievalConfig` 类型与校验、平台设置 API、租户有效配置覆盖、智能体配置覆盖逻辑、Session 搜索和 Integration RAG handler。
- 前端：平台设置新增检索策略页；知识搜索页移除租户检索编辑器；智能体编辑器移除检索策略控件及前端默认值迁移逻辑。
- API：平台设置读写 DTO 扩展；Integration `top_k` 保持兼容并仅作为响应缩小值；批量响应结构保持按 query ID 分组并增加整批预算约束。
- 数据：不删除租户和智能体历史字段；新运行时统一忽略这些旧覆盖值，降低迁移风险并支持必要时回滚。
- 测试：覆盖角色权限、所有问答/搜索入口的有效配置一致性、Integration 单条/批量一致性、旧数据兼容和前端入口可见性。
