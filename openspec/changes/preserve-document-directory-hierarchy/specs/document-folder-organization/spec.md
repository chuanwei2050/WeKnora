## ADDED Requirements

### Requirement: 知识分类与文档目录明确区分
系统 SHALL 将左侧由 `knowledge_tags` 管理的节点称为“知识分类”，将右侧由独立目录实体管理的节点称为“文档目录”；每棵文档目录树 SHALL 隶属于一个知识分类。知识分类继续决定文档 `tag_id`、分类搜索开关和 RAG 范围，文档目录只决定右侧浏览、目录管理与下载；目录跨分类迁移时必须连同其子树文档同步更新分类归属。

#### Scenario: 文件夹上传到选中分类
- **WHEN** 用户选中左侧知识分类后上传一个多层文件夹
- **THEN** 文件夹中的每个成功上传文档都继承所选分类的 `tag_id`
- **AND** 每个文档同时保留自身的右侧文档目录
- **AND** 所创建的目录链归属于当前分类
- **AND** 两种层级仍使用不同实体，目录不得出现在其他分类的右侧根级

#### Scenario: 同名分类与目录
- **WHEN** 左侧知识分类和右侧文档目录具有相同名称
- **THEN** 系统将二者作为不同实体展示和操作
- **AND** 进入右侧目录不会改变当前 `tag_id`
- **AND** 选择左侧分类会切换到该分类的右侧目录根级

#### Scenario: 调整文档知识分类
- **WHEN** 用户把文档从一个知识分类调整到另一个知识分类
- **THEN** 系统更新文档 `tag_id` 并清空 `directory_id`
- **AND** 文档出现在目标分类的右侧根级

#### Scenario: 删除知识分类时清理所属文档目录
- **WHEN** 用户通过既有分类删除流程删除一个知识分类
- **THEN** 系统在删除分类记录前清空该分类文档的目录关联并删除其右侧目录树
- **AND** 仅清空分类内容但保留分类时，右侧空目录结构继续保留

#### Scenario: 检索使用知识分类而非文档目录
- **WHEN** 系统按文件夹范围执行 RAG、显式文档校验或搜索开关过滤
- **THEN** 系统只使用左侧知识分类 ID 及既有子分类关系
- **AND** 不把右侧文档目录转换为标签或检索范围
