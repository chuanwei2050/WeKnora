## Why

当前“上传文件夹”会丢弃浏览器提供的相对路径，把所有文件平铺为知识条目，用户无法按原目录浏览或整体下载，也无法区分右侧文档目录与左侧知识分类。需要在不改变文档解析、治理、检索和引用原子性的前提下保留源目录层级。

## What Changes

- 为右侧文档目录建立独立实体，并让每棵目录树隶属于一个左侧知识分类；文件夹上传按经过校验的相对路径在当前分类内创建或复用目录层级，并让每个成功入库的文档关联其直属目录。
- 右侧文档区域同时展示当前目录的直属子目录和直属文档，支持在顶部文件类型控件旁通过面包屑逐级浏览；网格与列表视图遵循相同目录语义。
- 目录模式延续现有分页和滚动加载，目录与文档组成统一分页条目；支持稳定的名称、更新时间、大小、类型和状态排序。
- 右侧支持新建、重命名和删除任意目录；删除非空目录时经当前权限复核和单次确认后，按现有批量上限分片异步删除整棵目录及其中全部文档。
- 参考桌面文件管理器，支持在同一知识库右侧区域把文档或目录拖入目标目录；拖拽只表示移动归属，不提供拖拽排序。
- 每个文件和目录保留行内/卡片单项操作入口，并复用勾选后的批量操作栏承载多选操作；不新增页面右键菜单、剪切/粘贴快捷键或独立 CutSet；同分类“移动到文档目录”与跨分类“调整知识分类”保持两个明确入口。
- 支持下载任一右侧文档目录：服务端按当前用户可见范围生成 ZIP，并保留目录内相对层级与原始文件名。
- 明确区分左侧“知识分类”和右侧“文档目录”：分类继续决定 `tag_id`、权限、检索范围及其右侧目录空间，文档目录只承担当前分类内的组织、管理和下载，不参与召回、排序或引用标识。
- 存量目录迁入“未分类”的目录空间；存量文档及非文件夹入口创建的文档位于其当前知识分类的文档目录根级，用户主动创建的空目录可以独立保留。
- 保持现有按内容哈希去重语义；同一知识库内相同内容不会因目录不同而重复入库。
- 保持现有知识列表 API 的默认全量平铺语义；新目录界面通过显式根目录标记进入逐级浏览。

## Capabilities

### New Capabilities

- `document-directory-hierarchy`: 定义文档目录实体、上传建树、右侧逐级展示、目录增删改名、目录过滤与安全 ZIP 下载行为。

### Modified Capabilities

- `document-folder-organization`: 明确左侧文件夹是知识分类，右侧文档目录在语义和操作上保持独立，但目录树必须隶属于当前分类，上传文档继承当前分类。

## Impact

- 数据模型与迁移：新增文档目录表和目录删除协调记录，为目录增加分类归属，并为 `knowledges` 增加可空目录外键及查询索引，覆盖 PostgreSQL、SQLite、MySQL 和支持的初始化脚本；存量目录归入“未分类”。
- 后端：新增目录 CRUD、目录树与 ZIP 聚合能力；扩展并复用现有上传、知识列表、批量删除、跨库移动、文件读取、权限和检索链路。
- 前端：扩展现有知识库文档页、列表/网格、分页、排序、上传、选择及批量操作状态，加入面包屑、目录增删改名、移动、独立线框目录图标、目录下载及国际化文案。
- 兼容性：现有单文档下载、文档详情、解析、治理、知识库复制/移动、RAG、显式文件检索和引用继续以 `knowledge_id` 为边界；需验证这些流程不会把目录路径当作文件名或检索条件。
