## Context

当前上传和治理操作通常复用知识库管理权限，导致普通成员无法在不成为管理员的情况下向团队知识库投稿。现有知识版本状态机和“提交者不得自审”校验可复用，但缺少知识库级投稿策略、文档最初贡献者以及贡献者/审核员/管理员的职责边界。

## Goals / Non-Goals

**Goals:**

- 允许同租户成员在知识库明确许可时贡献并维护自己的未发布内容。
- 保证所有治理内容审批并激活后才进入正式检索。
- 支持已发布内容的新版本提案及无中断原子切换。
- 保持历史知识库、非治理数据和管理员现有能力兼容。

**Non-Goals:**

- V1 不允许普通成员编辑他人文档或为他人的 active 文档发起版本提案。
- V1 不引入跨租户投稿或自助公开知识库。
- 不通过放宽现有知识库管理权限实现投稿。

## Decisions

### 投稿策略属于知识库

知识库增加 `contribution_mode`：`closed` 仅管理员可写，`members` 允许同租户成员贡献自己的文档，`allowlist` 仅允许显式用户或角色。新建知识库必须显式选择，缺省为 `closed`；历史数据迁移为 `closed`，防止升级后静默扩大权限。

### 投稿必须与治理审批绑定

`members` 和 `allowlist` 只有在治理与审批启用时生效；否则普通成员投稿被拒绝，管理员继续使用原有直接上传流程。该选择避免未审核内容因旧索引流程直接可见。

### 所有权以文档和版本分别记录

`knowledge.created_by` 记录最初贡献者，`knowledge_version.created_by` 记录本次版本提交者。贡献权限只允许本人编辑或删除自己的 draft 和 rejected 版本。pending_review、approved、indexing 和 active 均不可直接修改；提交者可在审核产生决定前执行显式 `withdraw`，以审计状态转换将 pending_review 恢复为 draft。审核员和管理员可审核他人提交，任何人都不能审核自己的提交。

### 审批通过即进入索引并自动发布

V1 将 `approved → indexing → active` 作为自动流程，减少额外“管理员确认发布”状态。索引成功后原子更新 `current_version_id`；失败时保留旧 active 版本。首次发布在索引成功前不可检索。

### 治理与历史检索规则分流

治理知识只允许 `current_version_id` 指向的 active 且处于有效期内版本进入 RAG。未启用治理或 `current_version_id` 为空的历史知识继续使用现有 `parse_status`、`enable_status` 和索引可见性规则，不补造版本。

## Risks / Trade-offs

- [历史贡献者无法准确回填] → 缺失时回填租户管理员并写迁移审计，不猜测普通成员归属。
- [审批通过但索引失败] → 保持旧 active 可用，并允许对失败版本重试索引或重新提交。
- [投稿策略和治理开关组合复杂] → 在知识库配置边界校验非法组合，UI 不作为权限边界。
- [审核期间内容被修改导致审核对象漂移] → pending_review 后冻结版本内容，只允许显式撤回并重新提交。
- [成员离职后草稿失去维护者] → 管理员保留接管、驳回或删除未发布内容的能力并记录审计。

## Migration Plan

1. 增加 `contribution_mode` 和文档贡献者字段，历史知识库统一回填 `closed`。
2. 为缺失贡献者的历史文档回填租户管理员并生成迁移报告。
3. 新增贡献与审核权限判定，但保持原管理员路径有效。
4. 在试点知识库显式启用治理和 `members`/`allowlist`，验证完整状态流转与检索隔离。
5. 回滚时将知识库策略恢复为 `closed`；已发布 active 版本继续按现有检索路径服务。

## Open Questions

审核员 V1 采用知识库级授权，pending_review 撤回语义已固定。跨知识库审核员角色、普通成员对他人 active 文档发起版本提案以及跨租户投稿均留待后续 change。
