## 背景

当前系统能够上传音频附件，并通过现有 ASR 模型在服务端完成整段转写；前端没有麦克风录音、增量转写、语音播放或打断控制，后端也没有 TTS 模型接口。该能力属于“音频文件问答”，尚未形成任务书要求的连续语音输入、文本/语音反馈闭环。

本变更复用现有会话、消息、ASR 和流式回答能力，增加一条可选的语音交互路径。文本聊天仍是基础能力，浏览器、模型或设备不支持语音时必须可降级使用。

## 目标与非目标

### 目标

- 用户通过明确操作授权麦克风、开始和结束录音，并看到可纠正的增量转写。
- 最终转写作为普通用户消息进入现有多轮会话，不建立平行上下文。
- 支持将最终文本回答合成为语音、流式播放并由用户随时打断。
- 支持按智能体配置 ASR、TTS、语言、音色和自动播放，且默认关闭自动语音输出。
- 默认不长期保存原始录音，并支持私有化部署中的本地 ASR/TTS 模型。

### 非目标

- 不实现唤醒词、后台常开监听、说话人分离或电话接入。
- 不替换现有音频附件上传和批量转写流程。
- 不在本变更中实现语音生物识别或声纹认证。
- 不保证所有浏览器都支持同一种录音编码。

## 关键决策

### 1. 前端使用显式录音状态机

前端基于 `MediaRecorder` 和 Web Audio API 管理 `idle`、`requesting`、`recording`、`finalizing`、`error` 录音状态，并以独立播放状态管理 TTS。只有用户点击后才请求麦克风权限；页面不得自动开始监听。界面同时保留文本输入、停止/取消录音、编辑最终转写和取消发送入口，本期不承诺跨编码一致的录音暂停/恢复。

### 2. 增量转写采用专用会话，保留批量降级

后端定义流式 ASR 能力接口。前端先通过已认证 HTTP 接口获取绑定用户、会话和用途的 WebSocket 票据，再建立双向会话接收音频分片、返回部分文本和最终文本。票据有效期由 `voice.ws_ticket_ttl` 配置，默认 60 秒、服务端硬上限 5 分钟；WebSocket 升级时必须以原子操作校验并标记票据已消费，使并发重放最多只有一个连接成功。长期访问令牌不得放入 URL、客户端日志或代理访问日志。若所选 ASR 模型或浏览器不支持流式协议，前端在录音结束后将完整音频提交到复用现有 ASR 服务的临时批量转写接口，不创建知识附件或普通附件记录。部分文本只用于即时显示，不写入聊天历史。

### 3. 最终文本复用普通消息链路

用户确认后的最终转写通过现有消息发送接口提交，携带可选的语音来源元数据。后续问题继续加载同一会话历史，因此语音和键盘输入共享上下文、知识库权限、引用和 Agent 配置。

“连续对话”定义为用户在同一会话内连续执行多轮“主动开始录音—确认文本—接收回答”的按键式交互；系统不在回答结束后自动重开麦克风，也不实现后台常听。

### 4. TTS 作为独立模型能力

新增 `Synthesize(ctx, text, options)` 模型契约和 TTS 模型类型，选项包含语言、音色、语速和音频格式。服务端在最终回答文本确定后提供经过鉴权的流式合成接口；前端边接收边播放，并展示加载、播放、暂停、重播和错误状态。生成音频默认只在请求和播放生命周期内存在，不写入消息、对象存储或缓存；若启用持久化，必须复用显式保留策略。TTS 失败不影响文本回答可用性。

### 5. 打断只控制播放，不篡改回答

用户点击停止、开始新录音或发送新消息时，前端立即停止当前音频请求和播放。已经生成并持久化的文本回答保持不变；打断事件仅作为交互遥测记录，不删除消息。

### 6. 语音设置按智能体保存

智能体配置增加语音输入、语音输出、ASR 模型、TTS 模型、语言、音色和自动播放字段。服务端保存配置时验证模型类型和可用性。自动播放默认关闭；用户级无障碍偏好可覆盖自动播放，但不能绕过管理员禁用的能力。

### 7. 原始音频默认短暂处理

流式音频分片和临时批量 ASR 文件只在转写会话生命周期内处理，默认不写入持久化存储或附件表；成功、失败和主动取消均立即清理。进程崩溃或连接异常遗留的临时文件由启动时及周期清理器按 `voice.temp_max_age` 回收，默认 1 小时、服务端硬上限 24 小时，部署配置只能缩短。TTS 音频同样默认不持久化，服务端释放响应资源，前端在停止、播放结束或组件卸载时撤销临时 URL 和缓冲区。

若部署方因审计或数据集建设需要保留录音或合成音频，必须显式配置保留对象、期限和访问权限，并在录音或播放前向用户提示；已进入显式保留存储的对象不受临时清理器管理，而由保留策略清理。

## 集成边界

- 本变更复用普通消息链路维护上下文，不改变消息权限、知识检索和回答编排规则。
- 多智能体验证变更负责决定最终可见回答；TTS 只合成已经确定并有权访问的最终文本，不合成内部草稿。
- 私有化部署变更负责提供和验收内网 ASR/TTS 端点；本变更定义模型能力接口、鉴权和交互降级。
- 音频附件上传仍是现有独立能力；临时批量 ASR 不借用其持久化语义。

## 数据与接口影响

- 新增 WebSocket 票据、流式 ASR 会话、临时批量 ASR、TTS 合成接口和语音模型配置。
- 扩展智能体配置 API 与前端配置表单。
- 最终用户消息可增加输入方式和 ASR 模型等非敏感元数据。
- 现有音频附件、文本消息和流式回答接口保持兼容。

## 风险与权衡

- 浏览器编码与 ASR 输入格式不一致可能需要转码；服务端应限制格式集合并在边界校验。
- 连续音频传输增加连接和带宽压力；会话应有时长、分片大小和空闲超时限制。
- WebSocket 认证信息若出现在 URL 或日志中可能泄露；默认 60 秒、最长 5 分钟、原子单次消费的用途绑定票据和日志脱敏用于降低风险。
- 自动播放受浏览器策略影响，因此只能在用户已交互且浏览器允许时启用。
- TTS 会增加首段语音延迟；文本回答应先可见，语音作为增强通道。

## 迁移方案

1. 增加语音配置字段和模型能力类型，默认关闭语音输出。
2. 实现短期单次票据、流式 ASR 会话及临时批量 ASR 降级适配。
3. 实现前端录音、部分转写和最终确认流程。
4. 增加 TTS 服务接口、前端播放及打断控制。
5. 补充隐私提示、资源限制和不支持浏览器的降级说明。

## 待确认问题

- 首批部署使用的本地 TTS 引擎及其可用音色由部署环境确认。
- 如需保留原始录音，具体保留期限和合规提示文本需由业务方确认。

## 补充设计决策

### 8. 语音闭环纳入统一验收执行器

线上和离线语音基线必须复用普通消息链路和最终回答定义，验证“录音—最终转写—文本回答—TTS 播放—主动中断—同一会话继续追问”完整链路。测试记录 ASR/TTS 模型身份、首字文本时间、音频首块时间、播放中断和临时资源清理；不得只用单独的 ASR 或 TTS 连通性代替闭环通过。
