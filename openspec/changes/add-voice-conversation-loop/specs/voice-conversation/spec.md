## ADDED Requirements

### Requirement: 显式麦克风授权与录音状态

系统必须（MUST）仅在用户主动操作后请求麦克风权限，并向用户展示请求、录音、结束处理和错误状态以及停止控制。

#### Scenario: 用户开始语音输入

- **WHEN** 用户点击开始录音且浏览器授予麦克风权限
- **THEN** 系统进入可见的录音状态并开始采集音频
- **AND** 用户可以随时停止或取消录音

#### Scenario: 用户拒绝麦克风权限

- **WHEN** 浏览器拒绝麦克风权限
- **THEN** 系统停止语音采集并给出可操作提示
- **AND** 文本输入仍然可用

### Requirement: 增量与最终语音识别

系统必须（MUST）在所选模型支持流式 ASR 时，通过鉴权会话接收音频分片并返回可区分的部分转写与最终转写；部分转写不得直接写入聊天历史。WebSocket 建连 MUST 使用经已认证 HTTP 接口签发且绑定用户、会话和用途的票据，`voice.ws_ticket_ttl` 默认 60 秒且服务端硬上限为 5 分钟。系统 MUST 在 WebSocket 升级时原子校验并消费票据，使并发重放最多只有一个连接成功；不得在 URL 或日志中暴露长期访问令牌。

#### Scenario: 流式转写正常进行

- **WHEN** 用户持续录音且流式 ASR 会话可用
- **THEN** 前端显示随音频更新的部分转写
- **AND** 录音结束后系统返回一个最终转写供用户确认

#### Scenario: 重放或挪用 WebSocket 票据

- **WHEN** 客户端重复使用已消费票据，或将票据用于不同用户、会话或用途
- **THEN** 系统拒绝建立流式 ASR 会话
- **AND** 不接收或转发任何音频分片

#### Scenario: 票据过期

- **WHEN** 客户端在票据有效期结束后尝试建立流式 ASR 会话
- **THEN** 系统拒绝该连接且不消费音频分片
- **AND** 返回可重新申请票据的鉴权失败结果

#### Scenario: 并发重放同一票据

- **WHEN** 两个连接并发使用同一张尚未消费的票据
- **THEN** 原子消费操作只允许其中一个连接建立会话
- **AND** 另一个连接被拒绝且不接收任何音频分片

#### Scenario: 票据期限超过硬上限

- **WHEN** 管理员尝试将 `voice.ws_ticket_ttl` 配置为超过 5 分钟
- **THEN** 系统拒绝该配置并保持原值
- **AND** 返回允许范围说明

### Requirement: 批量 ASR 降级

系统必须（MUST）在浏览器或 ASR 模型不支持流式识别时，将录音结束后的完整音频交给临时批量 ASR 接口，并向用户说明当前为结束后转写。该接口可以复用现有 ASR 服务，但默认不得创建知识附件、普通附件或长期对象存储记录。

#### Scenario: 模型只支持批量转写

- **WHEN** 用户选择的 ASR 模型不支持流式识别
- **THEN** 系统允许用户完成录音并在结束后提交整段音频
- **AND** 最终文本仍可由用户确认后发送
- **AND** 转写完成或失败后按短期清理策略释放临时音频

### Requirement: 最终转写进入统一会话

系统必须（MUST）允许用户编辑和确认最终转写，并将确认文本作为普通用户消息发送到当前会话，继承现有多轮上下文、权限和知识库配置。

#### Scenario: 语音问题后继续文本追问

- **WHEN** 用户发送语音转写问题并随后使用键盘追问
- **THEN** 系统在同一会话历史中加载两条用户消息
- **AND** 后续回答能够使用前一条语音问题的上下文

### Requirement: 连续多轮采用显式按键交互

系统必须（MUST）支持用户在同一会话内重复完成多轮主动录音、文本确认和回答播放，同时不得在回答结束后自动重启麦克风或在后台持续监听。

#### Scenario: 完成一轮后继续语音追问

- **WHEN** 用户完成一轮语音问答后再次主动点击开始录音
- **THEN** 系统在原会话上下文中开始新的独立录音会话
- **AND** 在用户操作前麦克风保持关闭

### Requirement: 文本转语音与播放控制

系统必须（MUST）支持将最终回答文本通过配置的 TTS 模型合成为流式音频，并提供加载、播放、暂停、停止和重播控制；TTS 故障不得阻止文本回答显示。系统 MUST 只合成用户有权访问的最终回答，不得合成内部草稿。

#### Scenario: 播放最终回答

- **WHEN** 最终文本回答已生成且用户请求语音播放
- **THEN** 系统使用当前智能体配置合成并播放音频
- **AND** 用户可暂停、停止或重播该音频

#### Scenario: TTS 服务失败

- **WHEN** TTS 模型返回错误或超时
- **THEN** 系统停止语音加载并显示失败状态
- **AND** 已生成的文本回答和引用保持可用

### Requirement: 语音播放可被打断

系统必须（MUST）在用户停止播放、开始新录音或发送新消息时立即取消当前播放和未完成的音频请求，且不得删除或改写对应文本回答。

#### Scenario: 播放期间开始新提问

- **WHEN** 回答语音正在播放且用户开始新录音
- **THEN** 系统停止当前语音播放
- **AND** 保留原回答文本并开始新的录音会话

### Requirement: 智能体语音配置与默认值

系统必须（MUST）支持按智能体配置语音输入、语音输出、ASR 模型、TTS 模型、语言、音色和自动播放，并校验所选模型具备对应能力；自动播放必须默认关闭。

#### Scenario: 保存不兼容模型

- **WHEN** 管理员将非 TTS 模型配置为语音输出模型
- **THEN** 系统拒绝保存配置
- **AND** 指明模型能力不匹配

#### Scenario: 历史智能体没有语音配置

- **WHEN** 系统加载迁移前创建的智能体
- **THEN** 该智能体保持文本交互可用
- **AND** 不会自动播放语音

### Requirement: 私有化语音模型支持

系统必须（MUST）允许 ASR 和 TTS 使用部署环境中配置的本地或私有模型端点，不得强制依赖公网语音服务。

#### Scenario: 离线部署使用语音能力

- **WHEN** 管理员配置可用的本地 ASR 和 TTS 模型且环境无法访问公网
- **THEN** 语音识别与合成可通过本地端点完成
- **AND** 会话流程不发起必需的公网语音请求

### Requirement: 原始音频隐私与保留策略

系统必须（MUST）默认仅在识别或播放会话期间处理流式音频分片、临时批量 ASR 文件和 TTS 音频，不持久化这些音频；成功、失败或取消时 MUST 立即释放，异常残留 MUST 由启动时和周期清理器在 `voice.temp_max_age` 内回收。该期限默认 1 小时且服务端硬上限为 24 小时，部署配置不得延长硬上限。启用录音或合成音频保留时必须分别配置期限、访问权限并在录音或播放前提示用户。

#### Scenario: 使用默认隐私策略

- **WHEN** 用户完成一次语音识别且管理员未启用录音保留
- **THEN** 系统在会话结束后释放原始音频分片
- **AND** 仅保存确认后的文本及必要的非敏感处理元数据

#### Scenario: 使用默认策略播放 TTS

- **WHEN** 用户完成一次回答语音播放且管理员未启用合成音频保留
- **THEN** 系统释放服务端和客户端持有的临时 TTS 音频资源
- **AND** 不在消息、附件或对象存储中创建音频记录

#### Scenario: 异常退出遗留临时文件

- **WHEN** 进程或连接异常终止并遗留临时 ASR 文件，且文件年龄达到配置的 `voice.temp_max_age`
- **THEN** 启动时或周期清理器删除该临时文件
- **AND** 不创建附件或长期对象存储记录

#### Scenario: 临时清理期限超过硬上限

- **WHEN** 管理员尝试将 `voice.temp_max_age` 配置为超过 24 小时
- **THEN** 系统拒绝保存该配置并保持原值
- **AND** 返回允许范围说明

### Requirement: 不支持环境的可访问降级

系统必须（MUST）在浏览器缺少录音或音频播放能力时清晰说明限制，并保持键盘输入、文本回答和现有音频附件上传路径可用。

#### Scenario: 浏览器不支持 MediaRecorder

- **WHEN** 前端检测到浏览器不支持所需录音 API
- **THEN** 系统禁用实时录音入口并说明原因
- **AND** 用户仍可输入文本或上传受支持的音频文件

## ADDED Requirements

### Requirement: 语音连续交互基线
正式语音验收 MUST 验证同一会话内的“语音提问—最终转写—文本回答—TTS 播放—主动中断—继续追问”闭环，并记录 ASR/TTS 模型身份、文本首字时间、音频首块时间、播放中断和临时资源清理结果。

#### Scenario: 语音问答后继续追问
- **WHEN** 用户完成一轮语音提问并收到文本和语音回答后再次显式开始录音
- **THEN** 第二轮请求复用同一会话上下文并能引用第一轮最终转写和回答
- **AND** 验收结果包含两轮的模型、时序和资源清理记录

#### Scenario: 播放中主动中断
- **WHEN** 用户在 TTS 播放期间停止播放并开始新的语音提问
- **THEN** 当前音频请求和播放被取消
- **AND** 已持久化文本回答不被删除或改写，临时音频资源被释放
