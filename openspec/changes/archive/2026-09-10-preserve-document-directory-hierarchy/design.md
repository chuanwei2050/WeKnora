## Context

左侧节点来自 `knowledge_tags`，承担分类、搜索开关和 RAG 范围；右侧当前只有 `knowledges` 文档。浏览器虽提供 `webkitRelativePath`，上传代码却只提交 `file.name`，后端也没有目录模型。右侧目录还要支持新增、删除和改名，因此必须能脱离文档存在，不能只从路径临时推导。现有按 `file_hash` 去重及以文档 ID 为中心的消费链必须保持。

## Goals / Non-Goals

**Goals:**

- 建立独立的右侧文档目录树，支持任意上传层级、空目录、新增、改名和安全删除。
- 文件夹上传幂等创建目录链，右侧逐级展示并支持 ZIP 下载。
- 左侧知识分类拥有各自独立的右侧文档目录空间；两者实体和用途不同，但右侧目录必须归属于当前分类。
- 解析、治理、检索、显式文档选择和引用继续以文档 ID 为边界。

**Non-Goals:**

- 不提供拖拽排序，也不提供跨知识库拖拽移动。
- 不提供绕过确认的静默递归删除，也不为目录删除另建一套文档清理逻辑。
- 不让文档目录参与 RAG 范围、搜索开关、权限继承或标签管理。
- 不改变相同内容文件的现有去重规则，也不改变对象存储布局。

## Decisions

### 使用独立目录实体和稳定父子关系

新增 `knowledge_directories`，包含 `tag_id` 分类归属、父子关系、`normalized_name` 和删除状态。`tag_id` 必须属于同一租户和知识库；子目录必须与父目录具有相同 `tag_id`。`knowledges` 只增加可空 `directory_id` 与目录删除专用 `deletion_task_id`；非空 `directory_id` 必须与文档 `tag_id` 一致，目录删除 CAS 检查 `knowledge_id + parse_status=deleting + deletion_task_id`，不改造其他解析和治理更新。

目录名称在应用层执行 NFC、trim 和 case folding，持久化 `normalized_name` 并用于同分类同级唯一约束；唯一键包含 `tenant_id + knowledge_base_id + tag_id + parent_key + normalized_name`。排序按规范名称和稳定 ID 进行，要求同一数据库内分页稳定，不追求不同数据库字节级一致，也不新增持久化自然排序键。

目录以 ID 引用，改名只更新一行，不改写子孙或文档，也不触发解析/索引。`parent_id` 使用受限自引用外键，`directory_id` 使用 `ON DELETE RESTRICT`，服务层与数据库共同阻止孤儿。相比文档路径字段，该模型能表达空目录和可靠 CRUD；相比复用 `knowledge_tags`，不会污染分类与检索语义。

### 文件夹上传按路径幂等建树

multipart 增加可选 `directory_path`。前端从 `webkitRelativePath` 取得目录部分，基本文件名仍单独提交。服务端把 `\` 规范为 `/`，拒绝绝对路径、盘符、空段、`.`、`..`、NUL、超长名称、超出总长度或深度限制的路径。

上传只扩展现有 `KnowledgeHandler.CreateKnowledgeFromFile` 与 `knowledgeService.CreateKnowledgeFromFile`：目录服务在创建知识记录前解析或创建目录链，并把最终 `directory_id` 交给原流程。文件大小限制、FAQ/多模态分支、对象存储、治理元数据、哈希去重、解析任务入队与错误处理均继续由现有上传链负责，不建立第二套上传服务。

服务以当前 `tag_id` 和目录 ID 为基准逐段查找或创建相对目录链，以唯一约束和冲突后重查保证并发幂等，再关联最终目录 ID。新版单文件上传提交当前 `tag_id + directory_id`，新版文件夹上传提交当前 `tag_id + parent_directory_id + directory_path`；服务端拒绝分类与目录归属不一致。旧客户端省略目录参数时落在文档当前分类的根级。建议限制深度 32、单段 255 字符、UTF-8 总路径 1024 字节。批量上传不是整批事务，重复或失败可能留下合法空目录，用户可随后删除。

### 目录 CRUD 与递归删除

知识库级目录 API 复用现有同类操作权限：文件上传沿用投稿权限；新建、改名和移动目录仅允许文档编辑权限；删除目录沿用批量文档删除权限。该变更不重新定义原生库、共享库或投稿者角色边界。

目录无论是否为空都允许删除。服务端先计算完整子树的目录数、文档数和总存储大小，前端必须展示影响范围；非空目录删除必须通过现有批量文档删除授权。

目录只新增协调记录及分片记录，保存根目录、文档快照、每片稳定任务 ID、投递状态和完成状态，不新增逐文档任务项或目录专属 worker。文档按现有批量入口上限每片最多 200 条；确认事务预生成 Asynq TaskID 并持久化待投递分片，再复用 `MarkKnowledgeListDeleting`、`TypeKnowledgeListDelete`、现有 Asynq 入队与 `DeleteKnowledgeList` worker。提交后的投递失败由现有进程启动恢复/周期补投机制扫描待投递分片，稳定 TaskID 保证重复入队幂等。worker 按整片成功或失败回写，全部分片成功后触发后序目录清理。先在现有删除链内修正重复删除、资源已不存在和配额重复扣减问题。

删除锁写在被删根目录。PostgreSQL/MySQL 先按稳定 ID 锁知识库 sentinel，再锁源、目标和祖先；SQLite 使用 `BEGIN IMMEDIATE` 将同知识库目录写串行化。环检查在取得锁后重算。上传、目录 CRUD、移动、同步和删除确认全部使用该协议，防止 TOCTOU、双向移动成环和死锁。

删除预检在具有管理权限的上下文中计算完整子树，不套用普通查看者可见性，返回目录数、全部文档数、总存储大小和短期 `confirmation_token`。Token 是服务端持久化的高熵随机值，只保存摘要，日志不得记录明文；它绑定租户、知识库、根目录、操作者、文档/目录 ID 与更新时间形成的快照摘要及过期时间。正式删除必须重新校验操作者当前租户、知识库和批量删除权限，再在事务中锁定根目录、重算摘要并原子消费 Token；Token 已用、过期、权限撤销或子树变化均不得开始删除。

空目录可立即删除。非空目录在同一事务中创建协调记录并设置目录锁，随后通过现有批量删除入口标记文档并入队；现有 worker 成功软删除全部文档后，协调器按后序删除目录。失败仍使用现有任务重试和错误处理，目录保持锁定。

若某分片失败，该片由现有 worker 整片幂等重试；已成功分片保持完成，失败分片内文档继续处于删除中并保留必要目录。协调记录只展示失败分片摘要，不承诺逐文档失败结果。所有分片成功前子树保持锁定，不提供取消、恢复可检索状态或人工解锁分支。

删除 worker 不信任队列 payload 中的作用域。每片执行前必须从协调记录加载快照，并以 `tenant_id + knowledge_base_id + knowledge_id + deletion_task_id` 校验/CAS；协调记录、任务或任一文档作用域不一致时整片拒绝执行并记录安全错误。

### 复用选择与批量操作栏执行移动，不新增右键和剪切状态机

顶部右侧操作区将“新建文件夹”和“添加文档”显示为相邻、同高的品牌色文字按钮，“新建文件夹”位于“添加文档”左侧，并与搜索、筛选和视图切换控件垂直居中；添加文档继续使用原下拉菜单，不新增自定义颜色体系。

右侧继续允许把文档或目录直接拖到同一知识分类内的目标目录项、面包屑祖先或根级；拖放只表示移动归属，不承担排序。除拖放外，用户先勾选条目，再从现有批量操作栏选择“移动到文档目录”。系统不新增页面右键菜单，不拦截浏览器默认右键，也不实现 `Ctrl+X`、`Ctrl+V`、剪切弱化样式、CutSet 或“粘贴到当前目录”。

列表操作列和网格卡片菜单保留单项操作入口：目录提供下载、重命名、移至目录、移至分类和删除；文档完整保留原有重建、跨知识库移动、删除及治理操作，并新增复用同一目录移动弹窗/API 的“移至目录”和左侧分类选择器的“移至分类”。复选后的批量操作栏不提供重命名，并按单项操作的相对顺序展示“下载、移至目录、移至分类、删除”；文件、目录或二者混选均可下载、移至分类和删除，适用的治理操作继续沿用已有 action 判定。混合移至分类由单个服务端事务同时处理文档和目录，多个选中条目下载合并为一个 ZIP，目录保留顶层名称和内部层级，直接选中的文档放在归档根级。列表表头全选同时覆盖当前页全部可操作文档和目录，网格与列表共享同一选择集合。新建目录、上传文件和上传文件夹仍位于顶部工具栏，目录打开和文档预览仍使用已有直接点击入口。权限或生命周期不允许时沿用现有 action 判定置灰或隐藏，不建立第二套权限模型。

多选同时包含目录及其后代时，客户端和服务端都将后代折叠到最外层选中目录；移动到原父级视为无操作。拖动已选条目移动当前选择，拖动未选条目只移动该项；网格和列表一致。普通目录视图空白 drop 表示当前目录，搜索结果视图禁止空白 drop。

本变更不新增文档重命名，目录重命名也只保留在单项操作中；批量栏不显示重命名。文档“名称”可能分别指标题、原始文件名、下载名和引用标题，需另行定义后才能加入。批量栏、顶部按钮、直接点击和拖放复用同一既有 action/API 链路，不维护平行逻辑。

移动在单个数据库事务内锁定源对象、目标目录及必要祖先链，复查租户、知识库、`tag_id`、权限和整棵子树删除状态后提交。目录同分类移动不得移入自身或任一子孙；跨分类“移至分类”将选中的目录根提升为目标分类根级，子目录、文档 `directory_id` 和相对层级保持不变，并在提交后最多重试三次同步文档 Chunk 标签与检索索引；同步仍失败时记录待人工/后台对账的错误，但保留已提交结果，不向用户报告移动失败。目标分类根级存在规范化重名目录时整次操作冲突；文档继续遵循现有同目录同名策略，不借拖拽创建新知识记录。批量拖拽采用全成或全不成，避免部分条目移动后用户难以判断。跨知识库仍使用既有“移动到知识库”流程，不接受右侧拖放。

左侧“移至分类”和右侧“移至目录”保持两个明确命令。单独移动文档到其他分类时沿用现有语义，将 `tag_id` 更新并清空 `directory_id` 使其进入目标分类根级；移动目录到其他分类时保留目录树和文档 `directory_id`，并同步更新所有文档 Chunk 标签和检索索引。这样保持分类与目录归属一致，也不把两棵树混成一个选择器。

删除左侧知识分类时复用现有分类删除链；在真正删除分类记录前，原子清空该分类文档的 `directory_id` 并后序删除其右侧目录树，避免新增目录外键阻断原有分类删除。仅清空分类内容但保留分类时保留右侧空目录结构。

### 目录导航受当前知识分类限定

在现有 `ListPagedKnowledgeByKnowledgeBaseID` 及其 Repository 查询上增加可选 `directory_id`。不传时完整保留旧响应 envelope、字段、分页和默认排序；只有显式传 `__root__` 或真实目录 ID 才返回新 `entries` 结构并采用目录默认排序。旧模式仅在客户端显式传 `sort_by` 时改变排序，不新建平行列表链路。

目录模式返回统一分页的 `entries`，每项携带判别字段 `kind=directory|document`，并沿用现有 `page`、`page_size`、`total` 和前端滚动加载。请求必须携带当前 `tag_id`，`total` 是该分类当前直属目录数与直属可见文档数之和。目录固定排在文档之前并同样占用分页名额，避免一次返回无限多直属目录；服务先按目录数量消费 offset/limit，再以剩余额度查询文档，从而无需跨表 `UNION`。搜索模式不返回目录，只搜索当前分类及其既有分类子树中的文档，`total` 仅计算匹配文档。

接口增加 `sort_by` 与 `sort_order`。名称排序扩展并复用现有 `knowledgeDisplayNameOrder`，保留数字前缀、显示名和稳定 ID 规则；只修正该 helper 的数据库兼容性，不建立第二套排序链。其他字段参数化现有列表查询，目录仍固定在文档之前。右侧不提供拖拽自定义顺序。

右侧目录实体与知识分类实体保持独立，但每棵目录树由 `tag_id` 限定。当前目录面包屑放在顶部文件类型筛选控件之后，避免单独占用内容行。切换左侧分类时前端清空当前目录、面包屑、选择和分页，重新加载目标分类根级。关键词搜索返回当前分类范围内的扁平文档，并为每项返回只读 `directory_breadcrumb`（稳定 ID 与名称数组，根级为空）；该字段不替代 `knowledge_id` 或 `file_name`。清除后恢复逐级展示。

前端在目录、分类、关键词、类型、排序或目录结构变化后递增 query generation、取消可取消的旧请求、清空结果/选择/页码并从第 1 页重载；不可取消的旧响应因 generation 不匹配而丢弃。每页只允许一个在途请求，成功接收当前页后才推进 next page。删除当前目录或祖先的任务被接受后，立即导航到删除根最近的存活父级（没有则 `__root__`）并清除旧请求和面包屑状态；直接访问 deleting 目录返回统一删除中状态。目录与文档统一参与当前页选择，批量栏按选择类型收敛操作。

### 右侧目录使用独立视觉语义

左侧知识分类继续使用现有蓝色实体/电脑文件夹图标和 `computer-folder-icon` 样式。右侧文档目录使用 TDesign 中性线框 `folder`/`folder-open` 图标、独立的 `document-directory-icon` 样式和目录卡片/行；不得复用左侧图标组件、渐变、CSS 类或拖拽手柄。图标只是辅助信息，目录条目同时提供文本名称、`aria-label` 和可见的目录操作入口，网格与列表保持同一视觉语义。

治理可见性必须下推到 Repository 查询，在目录文档计数、搜索、总数统计和分页之前应用，禁止先分页再在 Handler 过滤。普通读取和 ZIP 只统计、返回当前用户可见文档；目录下载另外要求知识库编辑权限；目录删除预检与执行则在管理权限下处理子树全部文档。目录名称和层级是所属知识分类内由具备文档编辑权限的用户维护、可独立为空的组织元数据，不从文档可见性推导；具有知识库读取权限的用户在选中该分类时可见目录本身，即使其文档均不可见。这是明确的产品可见性边界，目录响应不得附带不可见文档的数量、名称、状态或其他元数据。

### 目录下载使用独立流式 ZIP 端点

新增以目录 ID 集合为目标的知识库级下载端点，同时保留单目录兼容路径；端点仅允许具有编辑权限的用户调用。端点从目录实体读取并校验其 `tag_id` 归属，负责聚合目录树和流式写 ZIP；每个文档的授权、治理可见性与原文件读取复用现有 `GetKnowledgeFile` 链路，不复制对象存储读取或文件下载逻辑。空目录返回含目录条目的有效 ZIP，多个目录合并到同一个 ZIP 并各自保留顶层目录名。ZIP 路径由服务端遍历目录实体产生并再次做 Zip Slip 防护；同路径同名文档用稳定序号消歧。响应头写出前完成权限、存在性、分类一致性和文件可读性预检。下载不依赖客户端传入的临时 `tag_id` 来裁剪内容。

### 文档消费链保持原有语义

解析、索引、图谱、治理、Agent 显式文档选择和引用继续使用 `knowledge_id`；目录不写入 chunk 内容或检索过滤器。重解析、重建和治理版本切换保持 `directory_id`。

普通 RAG、批量 RAG 和对话检索继续只接收 `knowledge_base_ids`、`knowledge_ids` 与左侧分类的 `folder_ids`/`tag_ids`。`folder_ids` 始终且仅由 tag Repository 校验和解释；不是合法或无权 tag 时返回 `invalid_folder_ids`，绝不查询 directory Repository。

主对话和悬浮聊天框复用同一对话与检索链。悬浮聊天框只按知识库 ID 建立范围，不引入右侧目录选择；主对话中的显式文件选择和 `@` 文档选择继续提交 `knowledge_ids`。旧知识列表调用省略 `directory_id` 时保持全库平铺；实际 `@` 搜索接口也必须返回所有活跃的子目录文档。

复用现有 `isKnowledgeDeleting` 判定，只在 `SearchKnowledge`、`SearchKnowledgeInScopes`、`@` 搜索和显式文档 ID 装载入口补齐排除 `deleting` 文档，确保新 RAG、批量 RAG、主对话、Agent 和悬浮聊天框不会消费正在删除的文档；不新增“活跃文档”服务。详情、预览、下载和既有历史引用沿用当前文档删除语义，不在本变更中统一重构所有装载入口。

回答引用继续保存并返回 `knowledge_id + chunk_id`，引用详情通过 `knowledge_id` 加载文档，通过 `chunk_id` 定位片段；面包屑只能作为实时、可选的展示字段，不能写入历史引用身份。目录新增、改名以及文档目录关联变化不得改写历史消息或使引用失效。

递归删除是唯一会改变消费可用性的目录操作。删除任务锁定子树后，其中的文档立即从新检索、显式选择和新对话上下文中排除；已生成消息及引用记录保持不变。删除中或删除完成后，引用详情若无法读取文档，统一沿用现有“引用文档不可用”反馈，不返回目录路径、部分文档内容或不同的越权错误。部分失败而保留的文档在恢复可用条件前不得参与新检索。

知识库复制到新库时先按现有标签复制规则映射 `tag_id`，再在对应目标分类内复制完整目录树并映射目录 ID。同步已有目标库时扩展现有按 `file_hash` 映射文档的流程，在已映射的目标分类内创建所需目录；只清理由本次同步事务新建且最终未引用的空目录，绝不删除目标库既有或用户创建的空目录。单文档跨库移动继续使用现有 `MoveKnowledge` Asynq 任务及复制/同步链，只在目标库对应分类内按源目录面包屑幂等创建目录链。

## Risks / Trade-offs

- [新增目录表增加迁移复杂度] → 使用简单邻接表和受限 CRUD，为父级列表与文档关联建立索引。
- [上传部分失败留下空目录] → 空目录是合法对象，结果逐文件报告，允许用户删除。
- [递归删除可能影响大量已索引知识] → 删除前返回影响摘要并二次确认，由目录协调记录关联并复用现有批量删除任务和 worker。
- [递归删除部分失败留下不完整子树] → 不回滚已完成的外部资源清理，保留失败文档和必要目录，返回失败摘要并支持幂等重试。
- [大目录 ZIP 占用连接] → 流式生成，并设置可配置的文档数和总原始大小上限。
- [恶意名称导致 Zip Slip] → 创建、上传建树和 ZIP 输出三处均做服务端校验。
- [搜索与分页产生遗漏] → 目录摘要与文档分页分离，分别测试逐级和搜索模式。
- [同内容跨目录被跳过] → 保留去重规则和已创建目录，明确报告重复。
- [旧调用者省略目录参数时少拿文档] → 省略参数严格保留全量平铺语义，仅显式根标记进入目录模式。
- [治理过滤在分页后执行造成泄露或缺页] → 将主体可见性作为 Repository 查询条件，在所有计数和分页前应用。
- [目录与文档混合分页出现重复或漏项] → 目录固定在前、统一计算 total、所有排序追加 ID，并在结构或查询条件变化时从第 1 页重载。

## Migration Plan

1. 新增 `knowledge_directories`、目录删除协调记录、约束和索引；目录增加 `tag_id` 并将存量目录迁入“未分类”，为 `knowledges.directory_id` 增加可空外键与索引，覆盖 PostgreSQL、SQLite、MySQL 和初始化脚本。存量文档显示在其当前知识分类根级。
2. 先部署目录 CRUD、导航和下载后端；旧前端仍可上传根级文档。
3. 发布提交相对路径、目录导航和 CRUD 控件的新前端。
4. 回滚数据库前必须确认不存在目录记录及非空 `directory_id`，否则拒绝降级以防丢失组织信息。
