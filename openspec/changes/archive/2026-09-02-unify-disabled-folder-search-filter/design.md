## Context

`knowledge_tags.search_enabled` 表达文件夹是否允许参与搜索。当前普通对话与 Agent 在 `buildSearchTargets` 中固定启用过滤，`@` 文件列表通过独立分页后过滤实现相同效果；Integration 单次与批量 RAG 默认不看搜索开关，仅在提供 `folder_ids` 时限制标签范围。普通文件夹正在增加最多两级的 `parent_id`，而现有逻辑只检查文件直接所属标签，不能让关闭父文件夹的状态覆盖子级。

本变更横跨 HTTP 请求、前端调用、SDK、检索目标构建和文件列表分页，但不改变文件夹持久化模型。权限校验、共享知识库授权和调用方显式选择的知识库范围仍是更外层边界。

## Goals / Non-Goals

**Goals:**

- 让所有相关入口使用同名、同语义的 `filter_disabled_folders` 请求字段。
- 字段缺失和 `false` 统一表示不应用搜索开关，`true` 才过滤。
- 父文件夹关闭时排除其所有后代中的文件。
- 让显式文件、显式文件夹、整库检索和 `@` 分页结果遵循同一判定。
- 保持租户隔离、知识库授权和共享知识库所有权边界。

**Non-Goals:**

- 不因启用过滤而自动搜索当前租户全部知识库。
- 不改变文件夹搜索开关的管理 UI、数据库字段或写入接口。
- 不改变 `folder_ids` 对公共子文件夹的既有扩展规则。
- 不引入任意深度通用树框架；实现只需正确消费当前受限层级模型。

## Decisions

### 请求字段统一命名，批量接口按 query 承载

所有入口使用 `filter_disabled_folders`。JSON 请求使用普通 `bool`，GET 文件搜索使用同名查询参数；缺失自然解析为 `false`。批量 RAG 将字段置于每个 query，而不是批次顶层，使同批查询可以独立选择策略。

相比保留对话与 Integration 的不同默认值，这一选择让调用契约真正一致；代价是旧对话调用方需要显式传 `true` 才能保持原行为。

### 过滤只收窄既有授权范围

系统先完成调用方知识库、共享知识库和显式文件授权解析，再在每个目标知识库所属租户内计算可搜索标签。过滤结果只与本次目标范围相交，不加载其他知识库为检索目标。

共享知识库必须使用知识库所有者的 `tenant_id` 查询标签，不能使用发起请求的当前租户 ID，否则会产生错误空集或跨租户判定。

### 集中计算祖先感知的允许标签集合

服务层集中读取目标知识库的真实标签，建立 ID 到标签的映射，并判定一个标签自身及其祖先是否全部 `search_enabled=true`。当前普通文件夹最多两级，可直接检查自身与父级；代码仍需对缺失父级或异常环路采取安全排除，避免脏数据绕过过滤。

相比在检索结果阶段逐文件回查，预先计算允许标签集合可以复用现有 `SearchTarget.TagIDs`，并避免向量结果召回后才丢弃造成 Top K 不足。`@` 文件列表复用同一判定能力，但保留其为维持正确分页而执行的补页逻辑。

### `folder_ids` 与搜索开关取交集

Integration 先按既有规则校验和解析 `folder_ids`，再在 `filter_disabled_folders=true` 时与可搜索标签集合取交集。合法文件夹因开关被排除不属于参数错误；交集为空时返回空结果。

显式 `knowledge_ids` 在开关过滤下落入被排除文件夹时跳过，不返回越权错误。只有文件不存在、未授权、超出知识库边界或违反显式 `folder_ids` 范围时继续使用既有错误。

### 策略进入统一检索目标构建边界

将布尔策略从当前内部硬编码调用提升到 QA/RAG 请求模型，并一直传递至 `buildSearchTargets`。对话、Agent、直接 RAG 和 Integration 不各自实现开关判断；它们只负责解析请求和传递策略。

## Risks / Trade-offs

- [旧版对话、悬浮窗或 `@` 调用未传字段后会暴露原本隐藏的文件] → 同一次发布中更新内置前端显式传 `true`，并在发布说明中标记外部调用方迁移要求。
- [父子文件夹变更尚在进行，两个 change 存在实现依赖] → 实现时以已合入的 `parent_id` 模型为基础；若层级变更尚未合入，先完成或协调该 change。
- [逐知识库列出全部标签增加查询] → 仅在字段为 `true` 时执行，沿用分页批量读取，并在一次请求内按租户和知识库缓存结果。
- [`@` 搜索先分页后过滤可能需要多次读取] → 保留有界补页策略，并用父级感知的允许集合替代逐页重复标签查询。
- [显式文件全部被过滤后调用方难以区分无命中与策略排除] → 按已确认语义返回空结果，不新增错误类型；日志记录被过滤数量供诊断。

## Migration Plan

1. 先完成服务层祖先感知过滤与请求模型字段，并保持缺省为 `false`。
2. 更新 Integration API、SDK 和文档，使新调用方按需显式传值。
3. 同步更新主对话、悬浮窗和 `@` 列表调用为 `true`，保持产品现有隐藏体验。
4. 部署后验证缺省/`false` 不过滤、`true` 过滤，以及批内混合策略。
5. 回滚时移除新字段传递并恢复旧入口硬编码；无数据库迁移需要回滚。

## Open Questions

无；字段缺省语义、批量字段粒度及父级继承规则均已确认。
