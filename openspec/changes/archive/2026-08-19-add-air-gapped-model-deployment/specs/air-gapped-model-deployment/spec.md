## ADDED Requirements

### Requirement: 线上基线先于内网切换

系统必须（MUST）支持先使用批准的线上模型完成业务能力验收并冻结模型配置、评测套件、提示版本和报告，再将模型角色切换到内网端点执行同一套验收。

#### Scenario: 冻结线上基线

- **WHEN** 前六个业务变更使用线上模型通过阶段验收
- **THEN** 系统保存可复现的模型、配置、数据集、阈值和结果快照
- **AND** 该快照可用于后续内网模型差异比较

#### Scenario: 内网模型尚未通过回归

- **WHEN** 某个内网模型角色未通过同一冻结验收规则
- **THEN** 系统不得将该内网配置标记为最终交付通过
- **AND** 报告列出相对线上基线的失败项

### Requirement: 全模型角色能力清单

系统必须（MUST）为 Chat、Embedding、Rerank、VLM、ASR、TTS、验证/反思、评测裁判以及启用时的解析/OCR 模型保存角色、协议、运行位置、流式能力、结构化输出、工具调用、输入模态、上下文、向量维度、并发和超时能力。VLM MUST 表示视觉语言模型角色，vLLM 只能作为推理服务引擎或提供方信息，不得替代模型角色。

#### Scenario: 反思智能体需要结构化输出

- **WHEN** 管理员将一个不支持所需结构化输出的模型绑定为验证角色
- **THEN** 系统拒绝启用该绑定
- **AND** 指明缺失的模型能力

#### Scenario: 评测裁判与解析模型启用

- **WHEN** 冻结验收配置需要模型裁判，或文档导入配置启用了模型解析/OCR
- **THEN** 部署清单必须包含对应角色绑定和能力探针
- **AND** 缺少任一必需角色时离线预检失败而不是回退公网

### Requirement: 协议与运行位置分离

系统必须（MUST）分别表达模型接口协议、运行位置和模型制品策略，不得仅依据 `local` 或 `remote` 推断模型是否位于公网。运行位置 MUST 由服务端根据规范化端点、批准端点注册表及连接期 DNS/IP 解析判定，不得信任普通用户提交的 `location` 绕过网络策略。

#### Scenario: 使用内网 OpenAI-compatible 服务

- **WHEN** 管理员配置一个位于私网的 OpenAI-compatible Chat 端点
- **THEN** 系统将其识别为 `private-network` 位置和 `openai-compatible` 协议
- **AND** 不要求将其伪装为 Ollama 模型

#### Scenario: 读取旧本地模型配置

- **WHEN** 系统读取仅包含 `source=local` 的历史模型
- **THEN** 兼容层将其映射为同机 Ollama 和现有模型获取策略
- **AND** 历史配置无需立即重建即可使用

### Requirement: 业务流程保持提供方无关

系统必须（MUST）使检索、问答、复杂度路由、图谱检索、验证、评测和语音流程依赖模型角色接口与能力，不得要求为线上和内网模型维护两套业务实现。

#### Scenario: 从线上模型切换为内网模型

- **WHEN** 管理员将已验证智能体的 Chat 和验证角色绑定替换为能力兼容的内网模型
- **THEN** 同一业务流程和 API 可以继续执行
- **AND** 无需修改该流程的业务代码或提示模板引用方式

### Requirement: 受控批准端点注册

系统必须（MUST）通过统一 `ApprovedEndpoint` 注册表管理管理员批准的内网模型、搜索、数据连接器、S3 兼容存储和自托管遥测端点，并校验 scheme、host、port、协议、TLS 策略、可穷举服务类别和允许用途。所有配置只能引用类别与用途匹配的端点，所有连接和重定向 MUST 再次执行 DNS/IP 与 SSRF 校验；普通租户不得通过任意 URL 访问未批准或用途不匹配的内网服务。

#### Scenario: 租户提交未注册私网地址

- **WHEN** 普通租户尝试保存指向未注册私网 IP 的模型配置
- **THEN** 系统拒绝该配置
- **AND** 不向目标地址发起连接

#### Scenario: 管理员批准内网模型地址

- **WHEN** 管理员注册一个私网模型端点且部署级 allowlist 包含该地址
- **THEN** 对应角色的模型连接检查可以访问该端点
- **AND** 连接仍执行 DNS、目标 IP 和重定向安全校验

#### Scenario: 跨用途使用已批准端点

- **WHEN** 一个端点只批准为 `object-storage`，但配置请求将其用作模型或遥测端点
- **THEN** 系统拒绝保存该配置
- **AND** 不因主机已在 allowlist 中而跳过用途校验

### Requirement: 严格离线模式禁止公网依赖

系统必须（MUST）在 `AIR_GAPPED_MODE` 启用时拒绝公网模型、公共 Web Search、公共数据同步、云端遥测、公网云存储和其他未批准或解析到公网的端点；系统 MAY 使用由管理员在 `ApprovedEndpoint` 中按正确用途注册并通过连接期校验的内网搜索、数据连接器、S3 兼容存储和自托管遥测。

#### Scenario: 离线模式配置公共模型

- **WHEN** 管理员在严格离线模式下尝试启用 `location=public` 的模型
- **THEN** 系统拒绝启用并指出公共端点
- **AND** 不发起测试或推理请求

#### Scenario: 离线模式启动存在已启用的公网遥测

- **WHEN** 应用以严格离线模式启动且存在已启用、未批准或解析到公网的遥测端点
- **THEN** 启动预检失败并指出该遥测配置
- **AND** 不向云端遥测地址发送数据

#### Scenario: 使用批准的内网数据与遥测服务

- **WHEN** 严格离线模式配置了已注册且解析到私网的 S3 兼容存储、数据连接器或自托管遥测
- **THEN** 系统允许访问这些明确批准的内网端点
- **AND** 同类未注册端点仍被拒绝

### Requirement: 禁止静默公共云回退

系统必须（MUST）在内网模型不可用、超时或能力不足时返回可诊断错误或按配置使用另一个已批准内网模型，不得静默调用公共云模型。

#### Scenario: 内网 Chat 模型超时

- **WHEN** 严格离线模式中的主 Chat 模型超时且没有已批准的内网备用模型
- **THEN** 请求以可诊断失败或保守回答结束
- **AND** 系统不调用任何公共云 Chat 端点

### Requirement: 预加载制品且运行时不下载

系统必须（MUST）在严格离线模式下只使用预加载的模型、镜像、解析资源和前端资源；缺失制品时快速失败，不得执行 Ollama pull、容器镜像 pull 或其他联网下载。

#### Scenario: Ollama 缺少配置模型

- **WHEN** 严格离线模式启动且 Ollama 中不存在清单要求的模型
- **THEN** 预检将该模型标记为缺失并阻止交付验收
- **AND** 系统不调用 Ollama 拉取接口

### Requirement: 角色级功能预检

系统必须（MUST）为每个已绑定模型角色执行最小功能探针，验证真实请求能力而非只检查端口可达，并输出能力、延迟、模型身份和失败原因。

#### Scenario: Embedding 维度不匹配

- **WHEN** 内网 Embedding 探针返回的向量维度与知识库配置不一致
- **THEN** 预检失败并报告期望与实际维度
- **AND** 系统不得使用该模型继续写入现有向量索引

#### Scenario: Chat 端点不支持工具调用

- **WHEN** ReAct 智能体绑定的内网 Chat 模型无法完成工具调用探针
- **THEN** 该智能体的离线能力预检失败
- **AND** 报告指出工具调用能力缺失

### Requirement: 统一安全模型传输

系统必须（MUST）使 OpenAI-compatible Chat、Embedding、Rerank、VLM、ASR、TTS、验证/反思、评测裁判和启用时的解析/OCR 模型使用受控的超时、取消、TLS、Header、SSRF 与连接期目标校验策略。

#### Scenario: 内网端点重定向到未批准地址

- **WHEN** 已批准模型端点返回指向未批准主机的 HTTP 重定向
- **THEN** 模型传输拒绝该重定向
- **AND** 记录不包含密钥的安全错误

### Requirement: 可验证的离线部署介质

系统必须（MUST）生成包含固定版本桌面 Lite 制品、应用镜像、依赖镜像、部署清单、迁移、配置模板和文档的离线介质，并为每个文件记录版本、架构、来源和 SHA-256 校验和；正式离线 override/values lock 与介质清单不得使用浮动 `latest` 标签或其他不可复现引用，但不得要求通用开发 Compose/Helm 默认值绑定客户专用版本。

#### Scenario: 导入完整离线包

- **WHEN** 操作者在断网环境导入离线包
- **THEN** 导入工具先验证全部文件校验和与目标架构
- **AND** 校验通过后可从本地介质加载所需镜像

#### Scenario: 离线包文件被替换

- **WHEN** 任一介质文件的 SHA-256 与清单不一致
- **THEN** 导入流程在使用该文件前失败
- **AND** 报告被替换或损坏的文件

### Requirement: 模型权重许可与完整性清单

系统必须（MUST）记录每个内网模型的名称、版本、协议、硬件要求、许可证、文件校验和和导入步骤；未经确认允许再分发的模型权重不得自动装入应用离线包。

#### Scenario: 模型许可证不允许再分发

- **WHEN** 模型清单标记权重不可随应用再分发
- **THEN** 打包流程仅保留客户自行获取和导入说明
- **AND** 预检在运行前验证客户导入文件的版本与校验和

### Requirement: 密钥不进入离线介质

系统必须（MUST）从离线介质和模型配置导出中排除真实 API Key、数据库密码、JWT 密钥和证书私钥，并要求在目标环境通过 secret 机制注入。

#### Scenario: 导出私有部署配置

- **WHEN** 管理员导出模型和部署配置用于离线交付
- **THEN** 导出文件保留非敏感端点与能力信息并脱敏密钥
- **AND** 导入预检列出必须重新注入的 secret

### Requirement: Compose 与 Helm 离线启动

系统必须（MUST）提供专用 Docker Compose 离线 override 和 Helm 离线 values/lock，使其在镜像已导入本地 Docker 或内网镜像仓库后无需公网拉取即可启动，并允许配置内网模型、存储、数据库和可选本地可观测服务。

#### Scenario: Helm 使用内网镜像仓库

- **WHEN** 操作者将离线清单中的镜像导入内网仓库并配置 repository、tag 和 pull secret
- **THEN** Helm 部署只从指定内网仓库获取镜像
- **AND** 启动过程中不依赖公共镜像仓库

### Requirement: 桌面 Lite 断网 profile 与单节点判定

系统必须（MUST）提供 `desktop-lite` 离线 profile，复用 Lite 支持的 SQLite、本地存储/内存组件以及同机或已批准内网模型，在无公网环境启动；该 profile MUST 禁用 GitHub 自动更新检查、后台版本请求和运行时模型下载，并通过离线介质执行人工升级。只有应用、全部启用且必需的数据组件和全部必需模型端点均被服务端判定为 `same-host` 时，`desktop-lite` 才能通过并声明纯 `single-node` 验收。

#### Scenario: 断网启动桌面 Lite

- **WHEN** 操作者在桌面制品、全部必需模型和数据组件均已预加载到同一主机且无公网出口的环境启动 `desktop-lite`
- **THEN** 应用使用 `same-host` 数据组件和模型完成适用的导入、检索与问答冒烟，并可执行 `single-node` 门禁
- **AND** 启动和运行过程中不请求 GitHub、公共模型或公共更新服务

#### Scenario: 桌面 Lite 使用批准的内网模型

- **WHEN** `desktop-lite` 在无公网环境使用位置为 `private-network` 的已批准必需模型端点
- **THEN** 系统允许执行适用的离线功能与质量验证
- **AND** `single-node` 门禁必须失败并列出该非 `same-host` 端点，不得生成纯单机通过结论

#### Scenario: 检查桌面更新

- **WHEN** `desktop-lite` 处于严格离线模式且用户打开关于或设置页面
- **THEN** 界面说明更新由离线介质管理并不发起自动检查
- **AND** 不访问 GitHub release API

### Requirement: 无公网出口端到端验收

系统必须（MUST）分别对 `desktop-lite`、`compose-airgap` 和 `helm-airgap` 的适用范围，在网络层禁止公网出口的环境中执行模型预检以及文档导入、索引、检索、回答、引用、适用的复杂路由、验证、语音和验收基准，并记录所有被阻止或异常的出站连接尝试。单节点与服务器负载结果 MUST 使用各自验收 profile，不得相互替代；使用任何 `private-network` 必需组件的运行不得通过 `single-node` 门禁。

#### Scenario: 完成最终断网验收

- **WHEN** 全部清单制品和内网模型已就绪且公网出口被禁止
- **THEN** 系统使用内网组件完成适用的冻结验收场景
- **AND** 报告证明没有成功的公网连接且各门禁结果可审计

### Requirement: 配置切换可回滚

系统必须（MUST）保存线上基线和内网部署的版本化模型绑定，使内网切换失败时能够恢复上一份有效绑定而不修改知识内容；Embedding 维度变化时必须使用独立索引或重建计划。

#### Scenario: 内网模型切换失败后回滚

- **WHEN** 内网模型部署未通过最终验收且环境策略允许恢复上一阶段
- **THEN** 管理员可恢复上一份有效模型绑定和部署配置
- **AND** 系统保留失败运行和回滚操作记录

## ADDED Requirements

### Requirement: 离线验收复用线上冻结套件
三种离线 profile MUST 使用与线上基线相同的冻结套件、提示、阈值、模型身份和评估口径，并通过同一端到端执行器验证适用的文档入库、检索、复杂度路由、图谱版本可见性、验证、语音和性能能力。

#### Scenario: 离线 profile 完成适用验收
- **WHEN** `desktop-lite`、`compose-airgap` 或 `helm-airgap` 在无公网环境启动正式验收
- **THEN** 系统使用线上冻结套件执行适用案例和性能门禁
- **AND** 报告保留 profile、组件位置、模型身份、出站审计和每个案例结果

### Requirement: 离线 profile 结果独立判定
离线验收 MUST 分别计算 `single-node` 与 `server-load` 门禁，不得用一个 profile 的通过结果替代另一个；使用 `private-network` 必需组件的运行 MUST 将 `single-node` 标记为失败并列出位置不符项。

#### Scenario: 内网模型不在同机
- **WHEN** `desktop-lite` 使用批准但位置为 `private-network` 的必需模型
- **THEN** 适用功能和质量结果可以保存
- **AND** `single-node` 门禁失败且报告列出该模型端点
