## Why

项目已经支持 Ollama、OpenAI-compatible/GPUStack 模型端点以及 Docker、Helm 私有部署，但这些能力仍是分散配置：缺少覆盖全部模型角色的内网能力检查、严格断网模式、可校验的离线安装介质和断网验收。客户要求所有模型与业务数据均在内网运行，因此需要在前六个业务变更先通过线上模型验证后，以同一模型契约完成最后一阶段的私有化替换与验收。

## What Changes

- 建立覆盖 Chat、Embedding、Rerank、VLM、ASR、TTS、验证/反思、评测裁判以及可选解析/OCR 模型的部署能力清单，校验流式输出、结构化输出、工具调用、上下文长度、向量维度等实际需求。
- 明确两阶段交付门禁：业务能力先使用线上模型跑通并冻结回归基线，随后替换为 Ollama 或由 GPUStack、vLLM 等引擎提供的内网 OpenAI-compatible 端点，复用同一套功能与验收用例；VLM 表示视觉语言模型角色，vLLM 表示推理服务引擎。
- 增加私有模型部署配置，区分“运行位置”和“接口协议”，统一管理内网端点、模型身份、能力、超时、并发和允许的网络范围，不再把 `local` 隐式等同于 Ollama。
- 增加严格离线模式：禁止公网模型、公共搜索/遥测/数据连接器和运行时自动下载，同时允许管理员批准的内网搜索、数据源、S3 兼容存储和自托管遥测；缺失本地依赖时快速失败，不得静默回退到公共云。
- 建立统一 `ApprovedEndpoint` 注册表，分类管理模型、搜索、数据连接器、S3 兼容存储和自托管遥测端点，并纳入 SSRF allowlist、连接期校验和角色/服务用途限制，阻止普通用户借任意 URL 访问内网服务。
- 提供全模型角色的预检、健康检查和端到端冒烟验证，输出可审计的通过/失败矩阵。
- 提供版本固定、带清单和校验和的离线镜像包生成与导入流程；版本固定落在专用离线 override/lock 清单，不破坏通用 Compose/Helm 默认开发配置；模型权重仅登记来源、许可、文件校验和和导入步骤，不擅自再分发。
- 提供桌面 Lite、Docker Compose 与 Helm 三种离线 profile 的配置、密钥注入、备份恢复、升级回滚和无公网出口验收说明；桌面 Lite 禁用 GitHub 自动更新检查。桌面 Lite 可使用批准的内网模型完成离线功能验证，但只有应用、所需数据组件和全部必需模型端点均为 `same-host` 时才能声明纯单机通过。

## Capabilities

### New Capabilities

- `air-gapped-model-deployment`: 覆盖线上基线到内网模型切换、模型能力预检、严格离线运行、离线介质和断网验收。

### Modified Capabilities

无。

## Impact

- 影响 `internal/types/model.go`、模型 provider/factory、模型管理与初始化检查接口，以及新增 TTS 和验证模型的配置路径。
- 影响 SSRF allowlist、HTTP client、外部连接器、网络搜索、遥测、桌面自动更新和 Ollama 自动拉取行为。
- 影响 Lite、Docker Compose、Helm 的专用离线配置、镜像版本策略、离线打包脚本和部署文档。
- 需要内网部署方准备符合接口和许可要求的模型服务、镜像仓库或离线镜像介质、模型文件及硬件资源。
- 依赖前六个变更的线上功能回归基线完成后再进入最终内网适配，但不要求前六个变更绑定特定云厂商。
