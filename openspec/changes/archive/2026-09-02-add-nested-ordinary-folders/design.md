## Context

知识库文件夹底层由 `knowledge_tags` 表承载。当前模型只有 `is_public`：`false` 表示根级普通文件夹，`true` 表示固定“公共知识”容器下的子文件夹，无法表达某个普通文件夹的直属子级。前端也把所有真实标签作为一个扁平集合渲染和排序。本次需要增加普通父子关系，但继续保持固定入口、公共子文件夹和现有检索标签语义不变。

## Goals / Non-Goals

**Goals:**

- 允许普通根级文件夹创建直属二级文件夹。
- 由服务端保证父子文件夹属于同一租户和知识库，且最大深度为两级。
- 让二级文件夹继续作为真实标签承载、筛选和检索文档。
- 平滑升级存量数据；所有已有普通文件夹继续保持根级。

**Non-Goals:**

- 不支持三级或任意递归文件夹。
- 不支持通过拖拽改变普通文件夹父级、层级或公共属性；普通二级只通过一级文件夹三点菜单中的明确入口创建。
- 不改变固定“公共知识”容器、公共子文件夹或“未分类”的数据语义。
- 不改变标签名称在同一知识库内唯一的现有规则。

## Decisions

### 使用可空 `parent_id` 表达普通二级关系

为 `knowledge_tags` 增加可空 `parent_id`。`parent_id = NULL AND is_public = false` 表示普通根级，`parent_id != NULL AND is_public = false` 表示普通二级，`parent_id = NULL AND is_public = true` 继续表示公共子文件夹。服务层拒绝 `parent_id != NULL AND is_public = true`。

相比复用 `is_public` 或引入通用路径字符串，父 ID 能直接表达用户选择的父级，不依赖名称解析；同时只允许父级自身 `parent_id = NULL`，即可在边界上阻止三级。

### 创建接口扩展可选 `parent_id`

现有创建标签接口增加可选 `parent_id`。提供父 ID 时，服务端读取父标签并验证：同租户、同知识库、非“未分类”、非公共子文件夹、父标签自身没有父级。未提供时保持现有根级或公共创建行为。

### 列表继续一次返回全部真实标签

标签列表响应为每个标签附带 `parent_id`，前端在内存中按父 ID 构造最多两层的展示树。这样不增加额外请求，也保留现有分页、统计和标签筛选契约。父级命中搜索或子级命中搜索时，前端显示必要的父子上下文。

### 一级删除存在子级时拒绝

删除普通一级文件夹前检查直属子级；存在子级时返回明确错误，要求先删除或处理子级。相比级联删除或自动提升子级，这一选择不会意外删除/重分类文档，也不引入用户未要求的隐式行为。

数据库同时增加最终完整性保护：PostgreSQL 为 `parent_id` 增加指向 `knowledge_tags.id`、使用 `ON DELETE RESTRICT` 的自引用外键；SQLite 使用等价触发器拒绝孤儿写入和删除仍有子级的父级，避免服务层“先检查、后写入”竞态产生孤儿记录。

### 折叠状态仅保存在前端

普通一级文件夹默认展开；用户可通过父级左侧箭头展开或折叠直属二级文件夹。折叠只影响当前页面展示，不改变筛选、检索或持久化数据。搜索文件夹时忽略折叠状态并显示命中的父子上下文；从父级新建二级文件夹时自动展开父级。

### 排序限定在同一父级

普通一级、公共知识直属文件夹、各普通父级的直属二级文件夹分别形成独立排序集合。拖拽源和目标必须属于同一集合；二级文件夹不得跨父级，普通一级与公共文件夹不得互相转换。创建子级时 `sort_order` 取该父级现有子级数量。

## Risks / Trade-offs

- [列表分页可能只取得部分父子集合] → 沿用现有超过排序上限时禁用排序的保护；前端只在完整加载时构树，测试覆盖父子响应。
- [旧客户端不了解 `parent_id`] → 字段为可选且创建默认仍为根级，保持向后兼容。
- [服务层检查存在并发竞态] → 数据库增加父 ID 索引，并使用 PostgreSQL 自引用限制删除外键与 SQLite 等价完整性触发器兜底；服务端继续校验同库与深度，并用迁移完整性和绕过前端的 API 测试覆盖。
- [父子展示可能诱导继续递归] → 只构造根级加一层直属子级的扁平展示序列，不引入递归组件或通用树框架。

## Migration Plan

1. 新增可空 `parent_id` 列和索引；PostgreSQL 增加 `ON DELETE RESTRICT` 自引用外键，SQLite 增加等价完整性触发器；存量行保持 `NULL`。
2. 部署后端模型、校验及响应字段，使旧前端仍可读取扁平标签。
3. 部署前端两层展示和创建入口。
4. 回滚时先确认不存在 `parent_id IS NOT NULL` 的行；否则回滚脚本拒绝或由运维先把子级提升为根级，避免静默丢失层级信息。

## Open Questions

无；拖拽改父级或改层级仍留待后续明确需求。
