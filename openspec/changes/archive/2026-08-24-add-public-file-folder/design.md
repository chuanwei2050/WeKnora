## Context

现有文档知识库把“全部文档”“未分类”和普通标签渲染为单层文件夹列表，标签本身没有公共归属字段。本变更需要在“未分类”之后增加固定的“公共文件”虚拟容器，并只允许真实标签作为其一层直属子文件夹。这里的“在未分类下面”指列表顺序紧随“未分类”，不表示“公共文件”从属于“未分类”。

## Goals / Non-Goals

**Goals:**

- 为每个文档知识库提供唯一的“公共文件”固定入口。
- 让编辑者通过“公共文件”右侧的 `+` 创建直属子文件夹。
- 让编辑者通过拖入或拖出“公共文件”直观地切换文件夹的公共归属。
- 文件夹树最多两层，且只有“公共文件”可以作为父级。
- 保持未分类和现有普通文件夹的展示、数量、排序、筛选与操作不变。

**Non-Goals:**

- 不支持任意普通文件夹嵌套或三级及更深层级。
- 不在没有用户拖拽操作时自动把现有普通文件夹迁移到“公共文件”下。
- 不在“公共文件”入口展示聚合文档数量，也不允许文档直接归属该入口。
- 不改变知识库之外的文件管理方式。

## Decisions

### 使用归属字段表达公共子文件夹

在持久化文件夹/标签模型中增加明确的公共归属字段，旧标签默认属于根级；被标记为公共的真实标签在界面中渲染到固定容器下。因为系统只支持根级和公共子级两种位置，而“公共文件”不承载内容，所以无需引入可递归的通用父级关系。相比父级 ID，这个受限模型直接排除了三级和任意嵌套，迁移与查询也更简单。

### 将“公共文件”作为无真实标签 ID 的固定容器

客户端根据接口返回的根级和公共子级集合构造唯一的“公共文件”容器，并将其固定显示在“未分类”之后、普通文件夹之前。容器使用前端保留键，不具有可提交给文档、FAQ、导入或同步写接口的真实标签 ID，因此不能承载内容，也不会被标签自动清理逻辑删除。已有名为“公共文件”的普通标签继续作为普通文件夹显示，不发生重命名、复用或唯一约束冲突。

### 公共文件不直接承载文档

“公共文件”是容器入口，点击用于展开或收起子文件夹；文档只能归属其直属子文件夹。因此入口右侧显示 `+` 而非数量。子文件夹继续显示各自的文档数量，点击后沿用现有标签筛选机制。

### 创建入口和权限保持收敛

只有具备知识库编辑权限的用户看到并可使用 `+`。创建请求通过受限的公共归属值声明新标签属于公共区域，不接收任意父级 ID。现有顶部新建文件夹入口仍创建根级普通文件夹，行为不变。

### 拖拽位置同时表达归属与顺序

根级普通区域与“公共文件”子级区域各自维护同级顺序：同一区域内拖拽只重排；把根级普通文件夹拖入“公共文件”时，服务端在一次原子操作中更新其公共归属并写入子级目标顺序；把公共子文件夹拖到公共区域之外的根级有效落点时，服务端取消公共归属并写入根级目标顺序。固定容器不参与任何排序，也不能成为被拖动项。

相比将两块区域完全隔离，跨边界拖拽让视觉层级直接对应公共归属，减少额外的属性切换操作。服务端接收来源区域、目标区域及目标完整顺序并进行事务校验；失败时前端恢复拖拽前状态并显示错误，避免只更新归属或只更新顺序。

### 限制跨边界拖拽落点

只有具备知识库编辑权限的用户可以拖拽。拖入操作的有效落点是“公共文件”容器或其子级列表间隙；拖出操作的有效落点是根级普通文件夹列表间隙。不能拖入某个公共子文件夹内部，也不能拖到“全部文档”“未分类”或其他普通文件夹上成为其子级，从交互和服务端两侧共同阻止三级或任意嵌套。

## Risks / Trade-offs

- [公共归属字段影响现有查询和数量统计] → 默认查询明确区分根级普通文件夹与公共子文件夹，并为两类查询增加回归测试。
- [已有同名普通文件夹造成视觉重名] → 固定容器不占用标签名称；保留用户数据和名称，并通过固定位置、`+` 与二级样式区分系统容器。
- [公共归属字段被内容写入接口忽略] → 公共子文件夹本身是真实可承载内容的标签，只有无标签 ID 的虚拟容器不能作为写入目标，因此无需在所有既有写路径增加特殊分支。
- [固定入口点击语义与现有筛选不同] → 仅用于展开/收起，并通过视觉缩进明确子级；不发送一个无意义的聚合筛选请求。
- [跨边界拖拽同时修改归属和两个区域的顺序，部分成功会导致状态错乱] → 使用单个事务接口原子校验和更新，失败时前端回滚乐观状态并重新获取列表。
- [拖出公共区域的意图可能不明确] → 仅根级列表的明确插入指示器接受拖出，悬停固定入口或文件夹节点不触发归属变更。

## Migration Plan

1. 增加公共归属字段，确保旧记录默认仍为根级普通文件夹；不创建任何“公共文件”标签记录。
2. 上线服务端查询、创建、归属变更及排序逻辑，再上线前端固定容器和 `+` 交互。
3. 回滚前端时，服务端保留新字段但旧客户端仍能把所有真实标签作为普通列表读取；回滚字段前先将公共归属统一恢复为根级。
