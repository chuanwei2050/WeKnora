## MODIFIED Requirements

### Requirement: 单层文件夹导航
文档知识库页面 SHALL 在左侧呈现受限层级的文件夹列表：除固定的“公共文件”入口可包含直属二级文件夹外，其他入口和普通文件夹均保持单层；系统不得显示知识库名称根节点、根据标签名称推导的层级编号或左侧文档子节点。

#### Scenario: 查看文件夹列表
- **WHEN** 用户打开文档知识库
- **THEN** 系统依次显示固定的“全部文档”“未分类”“公共文件”入口以及按持久化顺序排列的普通文件夹
- **AND** “公共文件”显示在“未分类”之后
- **AND** 普通文件夹和“公共文件”的直属子文件夹显示文件夹图标、完整名称和文档数量

#### Scenario: 查看公共文件入口
- **WHEN** 用户查看“公共文件”入口
- **THEN** 系统在名称右侧不显示文档数量
- **AND** 对具备知识库编辑权限的用户显示 `+` 创建按钮
- **AND** 已创建的直属子文件夹以二级缩进显示在“公共文件”下方

#### Scenario: 标签名称包含层级分隔符
- **WHEN** 普通文件夹或公共子文件夹名称包含 `-` 或数字层级样式
- **THEN** 系统将完整名称显示为一个文件夹且不从名称推导子级

#### Scenario: 点击普通文件夹或公共子文件夹
- **WHEN** 用户点击普通文件夹或“公共文件”的直属子文件夹
- **THEN** 右侧列表只显示属于该文件夹的文档
- **AND** 左侧不展开文档节点

#### Scenario: 点击公共文件入口
- **WHEN** 用户点击“公共文件”入口
- **THEN** 系统仅展开或收起其直属子文件夹
- **AND** 不将“公共文件”作为文档归属或聚合筛选条件

#### Scenario: 点击全部文档
- **WHEN** 用户点击“全部文档”
- **THEN** 系统清除标签筛选并显示该知识库的全部可见文档

### Requirement: 文件夹顺序管理
系统 SHALL 允许具备知识库编辑权限的用户拖拽普通文件夹和公共子文件夹调整同级顺序，并通过跨越“公共文件”边界的拖拽改变文件夹归属；每次操作 MUST 原子化持久化归属及受影响区域的完整顺序。

#### Scenario: 在根级区域内排序
- **WHEN** 具备编辑权限的用户把根级普通文件夹拖到根级区域的新位置
- **THEN** 系统只调整根级普通文件夹顺序且不改变其归属
- **AND** 刷新页面后保持该顺序

#### Scenario: 在公共区域内排序
- **WHEN** 具备编辑权限的用户把公共子文件夹拖到“公共文件”内的新位置
- **THEN** 系统只调整公共子文件夹顺序且不改变其归属
- **AND** 刷新页面后保持该顺序

#### Scenario: 拖入公共文件
- **WHEN** 具备编辑权限的用户把根级普通文件夹拖到“公共文件”的有效落点
- **THEN** 系统将其变更为“公共文件”的直属子文件夹并插入目标位置
- **AND** 归属变更与根级、公共区域顺序在一次操作中原子化持久化

#### Scenario: 拖出公共文件
- **WHEN** 具备编辑权限的用户把公共子文件夹拖到根级普通文件夹区域的有效落点
- **THEN** 系统清除其公共父级并将其恢复为根级普通文件夹
- **AND** 归属变更与公共、根级区域顺序在一次操作中原子化持久化

#### Scenario: 固定入口不可排序
- **WHEN** 用户查看“全部文档”“未分类”和“公共文件”
- **THEN** 三个入口保持在普通文件夹之前且不能被拖拽

#### Scenario: 拒绝无效跨边界落点
- **WHEN** 用户尝试把文件夹拖入公共子文件夹、普通文件夹、“全部文档”或“未分类”成为其子级
- **THEN** 前端不接受该落点
- **AND** 服务端拒绝任何绕过前端形成非法层级的请求

#### Scenario: 普通用户查看文件夹
- **WHEN** 不具备编辑权限的用户查看文件夹列表
- **THEN** 系统不显示拖拽能力但允许点击筛选

#### Scenario: 服务端拒绝无效排序或归属集合
- **WHEN** 拖拽请求包含重复 ID、其他知识库的 ID、非法父级或缺少受影响区域的当前文件夹
- **THEN** 服务端拒绝请求且不更新任何文件夹归属或顺序

#### Scenario: 拖拽持久化失败
- **WHEN** 跨边界归属变更或同级排序持久化失败
- **THEN** 前端将文件夹恢复到拖拽前的位置和归属
- **AND** 显示失败提示并重新获取文件夹列表

#### Scenario: 文件夹集合加载不完整
- **WHEN** 任一受影响区域的文件夹总数超过当前页面取得的数量
- **THEN** 前端禁用涉及该区域的排序和跨边界拖拽且不提交不完整的集合

## ADDED Requirements

### Requirement: 公共文件子文件夹管理
系统 SHALL 为每个文档知识库呈现唯一、受保护且不对应真实标签 ID 的“公共文件”固定容器，并且只有该容器可以显示直属二级文件夹；文件夹层级 MUST 不超过两层。

#### Scenario: 编辑者创建公共子文件夹
- **WHEN** 具备知识库编辑权限的用户点击“公共文件”右侧的 `+` 并提交有效名称
- **THEN** 系统在“公共文件”下创建一个直属二级文件夹
- **AND** 新文件夹显示在“公共文件”下方而不是根级普通文件夹列表中

#### Scenario: 无编辑权限用户查看公共文件
- **WHEN** 不具备知识库编辑权限的用户查看文件夹列表
- **THEN** 系统不显示“公共文件”右侧的 `+`
- **AND** 用户仍可查看并选择其有权访问的公共子文件夹

#### Scenario: 拒绝普通文件夹创建子级
- **WHEN** 客户端请求以“公共文件”之外的文件夹作为父级创建文件夹
- **THEN** 服务端拒绝请求且不创建文件夹

#### Scenario: 拒绝创建第三级文件夹
- **WHEN** 客户端请求以公共子文件夹作为父级继续创建文件夹
- **THEN** 服务端拒绝请求且不创建文件夹

#### Scenario: 保护公共文件入口
- **WHEN** 编辑者尝试重命名、删除或拖拽“公共文件”入口
- **THEN** 系统拒绝该操作

#### Scenario: 公共文件不承载内容
- **WHEN** 任一文档、FAQ、导入、批量移动或数据同步流程选择标签目标
- **THEN** “公共文件”固定容器不提供真实标签 ID 且不能作为目标
- **AND** 公共子文件夹仍作为真实标签正常承载内容

#### Scenario: 存在同名普通文件夹
- **WHEN** 知识库已有名为“公共文件”的普通文件夹
- **THEN** 系统保留该普通文件夹的名称、内容和根级归属
- **AND** 固定的“公共文件”容器仍独立显示且不创建同名标签记录

#### Scenario: 现有文件夹保持不变
- **WHEN** 用户创建、查看或选择根级普通文件夹且未执行跨边界拖拽
- **THEN** 系统保持变更前的单层展示、数量显示和操作行为
- **AND** 不自动将任何现有普通文件夹移动到“公共文件”下
