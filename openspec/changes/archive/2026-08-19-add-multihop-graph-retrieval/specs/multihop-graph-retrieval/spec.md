## ADDED Requirements

### Requirement: 类型化图路径查询
系统 SHALL 提供类型化图路径查询能力，输入至少包含由服务端根据当前身份解析的授权命名空间、种子实体、最大深度和结果上限，输出包含有序节点、边、路径分数及证据 chunk；终端用户不得提交任意 Cypher。

#### Scenario: 查询两个测评概念的关联
- **WHEN** 已授权用户查询两个存在图谱路径的软件测评实体
- **THEN** 系统返回连接实体的有序路径、关系类型和相关证据 chunk
- **AND** 返回数据包含实际 edges 而不是仅有文本搜索结果

### Requirement: 有界多跳遍历
图查询 MUST 在扩展期间限制最大深度、每个父节点的分支数、展开节点数、结果数和执行时间；最大深度 MUST 有服务端硬上限且不得被客户端突破，不得只在所有路径生成后用结果 `LIMIT` 冒充分支限制。Cypher 中无法参数化的标签和关系类型片段 MUST 仅由服务端枚举生成，实体、作用域和其他值 MUST 使用参数绑定。

#### Scenario: 稠密图达到预算
- **WHEN** 查询在达到时间或展开节点预算前仍有更多路径
- **THEN** 系统停止扩展并返回已排序的部分结果
- **AND** 结果标记为已截断及对应原因

### Requirement: 命名空间与关系约束
系统 MUST 将遍历限制在用户已授权的 tenant、knowledge base 和允许访问的 knowledge ID 集合内，并 MUST 仅遍历知识库配置允许的关系类型和方向。共享规范关系只有在至少存在一条属于允许 knowledge ID 集合的关系证据时才能参与遍历，返回结果 MUST 过滤掉未授权证据。客户端提交的作用域只能缩小、不得扩大服务端解析的授权范围。

#### Scenario: 请求越权知识库
- **WHEN** 用户请求包含未获授权的知识库 ID
- **THEN** 系统拒绝该作用域且不得返回其节点、边或 chunk

#### Scenario: 请求未知关系类型
- **WHEN** 请求指定的关系类型不在知识库 `ExtractConfig` 中
- **THEN** 系统拒绝整个图查询并返回允许的关系类型列表
- **AND** 不执行部分关系类型的隐式查询

#### Scenario: 关系仅由未授权文档支撑
- **WHEN** 当前用户可见规范实体，但连接它们的关系证据全部来自该用户无权访问的 knowledge ID
- **THEN** 系统不得沿该关系继续扩展或返回该边
- **AND** 结果中不得泄露未授权的 chunk、knowledge 或文档信息

### Requirement: 跨文档规范实体与关系证据
系统 SHALL 以 tenant ID、knowledge base ID、规范化实体类型和规范化名称组成的类型化唯一键，在知识库作用域内将同类型别名归一到规范实体，同时保留各文档中的实体实例；同名但类型不同的实体 MUST 保持分离，歧义别名 MUST 进入冲突处理而不得静默合并。每条规范关系 MUST 保存由端点规范实体、关系类型、方向、chunk ID、knowledge ID、文档版本和抽取来源组成的证据集合。删除或重建单个文档时，系统 MUST 只移除该文档贡献的实例和关系证据，不得在仍有其他证据时删除共享规范实体或关系。

#### Scenario: 两份文档提及同一实体
- **WHEN** 标准文档和项目经验文档分别以规范名称或别名提及同一测评方法
- **THEN** 系统将两个文档实例关联到同一知识库级规范实体
- **AND** 关系证据分别保留各自的 chunk、knowledge 和版本来源

#### Scenario: 不同类型实体具有相同名称
- **WHEN** 同一知识库中的工具实体和测试方法实体具有相同归一名称
- **THEN** 系统使用实体类型形成两个不同的规范实体键
- **AND** 不因名称相同而合并实例、关系或证据

#### Scenario: 删除共享实体的一份来源文档
- **WHEN** 一个规范实体或关系仍被其他文档证据引用且其中一份来源文档被删除
- **THEN** 系统仅删除该文档贡献的实例和证据
- **AND** 共享规范实体和剩余关系证据仍可查询

### Requirement: 跨文档路径
在同一授权知识库内，系统 SHALL 通过规范实体对齐支持路径节点引用不同知识文档，并保留路径中每段关系对应证据的 chunk ID、knowledge ID、文档标题和版本。

#### Scenario: 标准与项目经验跨文档关联
- **WHEN** 图谱中标准条款实体与项目经验实体通过中间测评方法相连
- **THEN** 系统返回跨文档路径及每一段关系对应的来源文档
- **AND** 不得用节点来源推断或伪造缺失的关系证据

### Requirement: 路径排序与去重
系统 SHALL 按种子匹配、关系权重、路径长度衰减和证据相关性计算可重复的路径分数，MUST 去除循环路径和重复节点序列，并按分数降序返回。

#### Scenario: 多条候选路径
- **WHEN** 两个实体之间存在多条不同长度和权重的路径
- **THEN** 系统优先返回总分更高的非循环路径
- **AND** 相同节点序列只出现一次

### Requirement: 文本检索融合
普通问答启用图检索时，系统 SHALL 并行执行图路径检索与现有向量/关键词检索，并在统一去重、rerank 和 merge 前标记结果来源。

#### Scenario: 图检索补充文本召回
- **WHEN** 图路径提供了文本检索未召回的相关 chunk
- **THEN** 该 chunk 以 `MatchTypeGraph` 进入后续 rerank
- **AND** 最终引用仍指向原始文档位置

### Requirement: Agent 图谱工具返回真实图数据
`query_knowledge_graph` SHALL 调用图路径查询服务并返回真实 nodes、edges、paths 和 citations，不得仅以 `HybridSearch` chunk 列表冒充图查询结果。

#### Scenario: Agent 调用图谱工具
- **WHEN** Agent 对启用图谱的知识库调用 `query_knowledge_graph`
- **THEN** 工具结果包含至少一条命中路径的节点和边
- **AND** 前端能够用结构化数据展示该路径

### Requirement: 无图或失败时降级
Neo4j 未启用、知识库未配置图谱、未找到路径或图查询超时时，系统 MUST 保持现有文本问答可用，并清楚记录降级原因。

#### Scenario: Neo4j 不可用
- **WHEN** 图查询返回连接错误而向量/关键词检索可用
- **THEN** 请求继续使用文本检索完成
- **AND** 用户不会收到图数据库内部错误堆栈

### Requirement: 路径可追溯性
每条返回路径 MUST 能回溯到构成该路径的实体实例、规范实体、关系证据、chunk ID、knowledge ID 和版本信息（若知识治理已启用）。

#### Scenario: 用户展开推理路径
- **WHEN** 用户在答案中展开一条图谱依据
- **THEN** 系统展示关系顺序和每个证据来源
- **AND** 用户可打开对应原文位置

### Requirement: 旧图重建与切换
系统 MUST 提供可重复执行的图谱重建流程，通过原始文档重新抽取并将现有按文档隔离且缺少关系证据的图数据写入新模型；只有存在可核验的权威抽取产物时才允许从该产物回填，MUST NOT 从节点 chunk 或其他节点属性猜测关系证据。在重建完成并通过计数及抽样校验前，不得宣称旧图已具备跨文档可追溯能力。

#### Scenario: 升级已有知识库图谱
- **WHEN** 运维人员对已有 Neo4j 知识库执行升级
- **THEN** 系统在隔离的新命名空间或新模型中重建规范实体、文档实例和关系证据
- **AND** 仅在节点、关系、证据计数与抽样路径校验通过后切换查询流量

## ADDED Requirements

### Requirement: 治理版本图谱隔离
启用知识治理时，图谱数据 MUST 按知识版本写入隔离 namespace；`draft`、`pending_review` 和未发布的 `indexing` 版本不得写入生产 active namespace。未启用治理时可以继续使用兼容的 knowledge 级 namespace。

#### Scenario: 待审核版本抽取关系
- **WHEN** 一个启用治理的知识产生 `pending_review` 版本并触发关系抽取
- **THEN** 抽取结果只能写入该版本的 staging namespace
- **AND** 当前生产图谱的节点、边和路径保持不变

### Requirement: 图谱 namespace 与版本原子切换
系统 MUST 仅在新版本图谱、向量和关键词索引均成功构建并通过证据版本校验后，同时切换图谱 active namespace 与知识的 `current_version_id`；任一索引失败时 MUST 保留旧生产版本。

#### Scenario: 图谱构建失败
- **WHEN** 新版本的图谱构建失败但向量索引已完成
- **THEN** 系统不得切换图谱 namespace 或 `current_version_id`
- **AND** 旧版本继续提供检索和图谱服务

### Requirement: GraphContext 只包含当前有效版本
图谱查询结果 MUST 在转换为 `GraphData`、`GraphContext` 或引用之前过滤掉非当前、未发布或已过期版本的节点、边、路径和证据；被过滤的路径不得参与排序或回答。

#### Scenario: 路径包含待发布证据
- **WHEN** 一条候选路径同时包含当前版本和待发布版本的关系证据
- **THEN** 系统移除待发布证据及其依赖路径
- **AND** 不得将该路径的关系用于回答推理
