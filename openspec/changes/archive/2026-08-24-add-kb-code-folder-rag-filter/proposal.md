## Why

外部系统目前只能依赖内部知识库 ID，缺少可由业务人员维护的稳定编码，也无法先按编码取得可筛选文件夹或在 RAG 请求中限定文件夹范围。需要补齐“人工编码 → 文件夹发现 → 按文件夹检索”的稳定 Integration API 链路。

## What Changes

- 在知识库基本配置的“知识库名称”下方增加可选的“知识库编码”字段，提示为“用于筛选知识库（可选）”。
- 知识库编码由人工填写，仅允许英文字母、数字、`-` 和 `_`，并在租户内按大小写不敏感方式唯一。
- 新增 Integration API：按知识库编码查询该知识库的外层普通文件夹列表；不返回“未分类”、虚拟“公共文件”容器或其下的公共子文件夹。
- 为单次和批量 RAG 搜索增加可选的文件夹 ID 多选字段。
- 未提供文件夹字段或提供空数组时不按文件夹筛选；提供非空文件夹 ID 数组时，检索范围为显式选择的文件夹，加上所选知识库内全部“公共文件”子文件夹。
- 对编码冲突、非法编码、越权知识库、跨知识库文件夹、无效文件夹 ID 以及文档/文件夹筛选冲突提供稳定错误响应和审计记录。

## Capabilities

### New Capabilities

- `knowledge-base-code`: 知识库人工编码的配置、格式、唯一性与查找语义。

### Modified Capabilities

- `integration-knowledge-api`: 增加按编码查询文件夹接口，并为单次和批量 RAG 增加文件夹范围筛选。

## Impact

- 影响知识库数据模型、数据库迁移、创建与更新校验、知识库配置界面和国际化文案。
- 影响 Integration API 路由、DTO、鉴权、审计、客户端 SDK 与 API 文档。
- 影响 RAG 检索范围构造及底层按 `tag_id` 过滤能力。
- 需要覆盖编码唯一性、文件夹列表排除规则、公共子文件夹自动并入及不传筛选时的兼容行为。
