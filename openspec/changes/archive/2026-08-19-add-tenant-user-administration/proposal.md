## Why

系统已经具备多租户数据模型和平台管理员角色，但缺少可操作的租户管理端、租户范围用户管理 API 与页面。关闭公开注册后，如果没有这些能力，平台无法完成租户开户、账号发放、角色调整和停用处置，不具备商用所需的基本管理闭环。

## What Changes

- 增加平台管理员专属的租户列表、新增、编辑、停用、启用和删除能力。
- 增加平台管理员与租户管理员可用的租户范围用户列表、创建账号、统一编辑和启用/禁用能力；编辑支持用户名、密码、普通成员角色和知识库可见范围，管理员角色创建后不可修改。
- 增加租户用户安全删除能力，仅允许删除未创建知识库、未创建文档或版本、且未执行版本审核的普通成员。
- 强制租户隔离和角色上限：租户管理员只能管理本租户，且不能创建或授予平台管理员角色。
- 停用租户后拒绝该租户用户继续访问业务 API；禁用用户或重置密码后撤销其现有令牌。
- 增加对应的平台管理页和租户管理页，并根据当前角色显示导航和操作。

## Capabilities

### New Capabilities

- `tenant-user-administration`: 定义平台租户生命周期管理、租户范围账号管理、角色边界、令牌撤销和管理页面行为。

### Modified Capabilities

无。

## Impact

- 影响租户、用户、知识库访问范围、认证令牌的服务与仓库接口、HTTP 路由和权限中间件。
- 新增平台租户管理和租户用户管理前端路由、API 客户端与页面。
- 需要覆盖平台管理员、租户管理员、普通成员三类角色和跨租户拒绝场景。
