## ADDED Requirements

### Requirement: 检索最小充分表集合
服务 SHALL 默认选择一张最高相关表；只有问题需要跨实体且存在可信关系路径时才扩展，最终候选 MUST 不超过三张表。

#### Scenario: 单表学历计数
- **WHEN** 问题只要求某一人力资源清单中的硕士人数
- **THEN** 服务只向 SQL 生成模型提供该清单对应的一张表

#### Scenario: 必要的跨表查询
- **WHEN** 问题需要两个实体且 Profile 中存在外键关系
- **THEN** 服务可提供两张相关表和关系，但不得加入无关第三张表

#### Scenario: 同一工作簿的明细页与汇总页得分接近
- **WHEN** 同一数据集版本内两张工作表的 Profile 排名差异不足以可靠判定唯一目标
- **THEN** 服务可向同一次 SQL 生成调用提供至多一个互斥候选页，由模型选择其中一张；不得默认扩展到三张表或把互斥候选用于 JOIN

### Requirement: 真实候选值作为生成证据
服务 SHALL 在生成 SQL 前检索问题对应的真实字段值，并将候选值、来源字段和匹配分数作为 evidence 传入模型。
在选定最小表集后，服务 SHALL 在该表集范围内执行一次无模型的词法值精检，以免全局值候选上限使目标表的真实写法丢失。

#### Scenario: 问题术语与存储值不完全一致
- **WHEN** 问题词与数据库真实值语义接近但字符不完全一致
- **THEN** 生成上下文包含检索命中的真实值，SQL 不得凭空发明过滤值

#### Scenario: 全局值候选被其他表占满
- **WHEN** 全局 Value Profile 前 N 条在选表后只剩少量目标表候选
- **THEN** 服务在目标表内重新检索真实值并与全局候选融合，不增加模型调用

#### Scenario: 相似名称属于不同业务类别
- **WHEN** 模型使用 OR 把两个近似名称扩张为同一个查询类别，但用户没有明确同时点名两者
- **THEN** 服务拒绝该 SQL，并要求结合问题限定词和 Profile 只保留一个标准值

### Requirement: Profile 检索必须具有可扩展索引和置信度门控
服务 SHALL 使用可索引的规范化名称/值检索生成 lexical 候选，并 SHALL 仅在标题、字段或值证据达到配置无关的最低置信信号时跳过向量兜底；结果非空本身不得视为证据充分。
查询编排 SHALL 通过一个 Profile 候选检索入口获得表、字段和值候选；并发 lexical 与共享问题向量兜底属于该入口内部实现，不得形成额外模型阶段。

#### Scenario: 问题仅命中常见二元词
- **WHEN** lexical 检索只得到无标题支持且单一弱字段命中的候选
- **THEN** 服务继续执行一次复用问题向量的语义检索，而不是直接确认该表

### Requirement: 限定词证据必须在首次生成前消歧
服务 SHALL 在不调用额外模型的前提下优先呈现与问题显式限定词一致的真实值，并标记主体近似但限定词冲突的候选不得合并为同一 OR 条件；实现不得包含业务专有名词硬编码。

#### Scenario: 近似主体具有不同括号限定
- **WHEN** 问题和值 Profile 中存在主体近似但括号限定不同的候选
- **THEN** 首次 SQL 上下文优先提供限定一致值，并把限定冲突候选作为排除证据

### Requirement: 宽表上下文必须有界且可恢复
首次模型调用 MAY 对超过字段预算的表仅保留检索相关列、键列和有界补充列；若进入唯一一次修复调用，服务 MUST 提供完整已发布 M-Schema，避免裁剪造成不可恢复的字段遗漏。

#### Scenario: 目标表包含大量字段
- **WHEN** 表字段数超过首次 Prompt 预算
- **THEN** 首次上下文保留命中目标字段且字段数有界，修复调用仍可访问完整 Schema

### Requirement: 正常查询仅调用一次主模型
服务 MUST 使用一次 OpenAI-compatible 主模型调用同时完成已检索上下文上的 SQL 生成；正常路径不得增加模型选表、critic、图表或结果总结调用。

#### Scenario: SQL 首次生成并执行成功
- **WHEN** 生成 SQL 通过 AST、EXPLAIN 并成功执行
- **THEN** 响应中的 `model_calls` 等于 1

### Requirement: SQL 生成必须绑定数据源方言
服务 SHALL 将已选择数据集的 PostgreSQL 或 MySQL 方言作为结构化上下文传给模型，生成结果 MUST 使用同一方言校验和执行；不得通过字符串替换转换方言。

#### Scenario: 查询 MySQL 数据集
- **WHEN** 检索选中的表全部属于同一 MySQL 数据源
- **THEN** 模型生成 MySQL SQL，且后续仅由 MySQL Adapter 校验和执行

### Requirement: 显式数据范围必须由 Profile 元数据解析
服务 SHALL 使用持久化的原始文件名和工作表名识别问题中的显式数据范围；实现 MUST NOT 依赖“清单/表格/工作表”等固定句式，也不得把命中的数据集名转换为行级 WHERE 条件。

#### Scenario: 用户以业务名称指定文件范围
- **WHEN** 问题文本与某个唯一原始文件名或工作表名存在可区分的连续元数据匹配
- **THEN** 服务仅在该 Profile 范围内检索和选表，并将范围作为非行级证据传给 SQL 模型
