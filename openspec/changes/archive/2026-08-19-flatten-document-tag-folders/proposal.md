## Why

文档知识库左侧目前把知识库名称和根据标签名推导出的多级树混在一起，既重复展示当前知识库，又让本质为单层分类的标签呈现出不存在的数据层级。需要将其收敛为可排序的单层文件夹列表，并让上传归属和未分类文档整理都围绕当前文件夹完成。

## What Changes

- 移除文档知识库左侧的知识库名称根节点及根据标签名称拆分出来的多级树，只保留单层文件夹列表。
- 为“全部文档”“未分类”和普通标签提供明确的文件夹式入口；点击入口后在右侧列表展示对应文档，不再在左侧展开文档。
- 管理员或具备知识库编辑权限的用户可拖拽普通文件夹调整顺序，顺序持久化后对其他用户生效；“全部文档”和“未分类”保持固定。
- 上传文件、批量上传、URL 导入及手工创建默认归入当前选中的文件夹；在“全部文档”或“未分类”上下文中创建时归入“未分类”。
- 在现有文档多选操作栏中增加“移动到文件夹”，支持管理员或编辑者将所选文档一次批量归类，并同步刷新列表和文件夹数量。
- 第一阶段的批量归类范围限定为当前已加载且可勾选的文档，不增加跨分页“全选全部结果”。

## Capabilities

### New Capabilities

- `document-folder-organization`: 规定文档知识库的单层文件夹导航、持久化排序、上传默认归属和批量归类行为。

### Modified Capabilities

无。

## Impact

- 前端文档知识库页面、文档列表批量操作栏、标签 API 客户端类型和相关国际化文案。
- 知识库标签 HTTP 路由、处理器、服务和仓储层；增加原子化保存文件夹顺序的能力。
- 复用现有 `knowledge_tags.sort_order` 和文档批量标签更新能力，不新增父子标签字段，不迁移标签名称或层级；仅将存量空标签文档归一化到已有或新建的“未分类”标签，不引入新的前端依赖。
