## Context

`knowledge_tags` 已经是知识库范围内的单层模型，文档通过单一 `tag_id` 与标签关联，并已有 `sort_order` 字段。当前文档页面额外按标签名称中的 `-` 构建临时层级、展示知识库根节点，并允许在左侧展开文档，这些表现与真实数据模型不一致。标签列表当前分页加载，排序仅支持逐标签更新；文档批量标签更新接口已经存在。

此外，文档上传在未传 `tag_id` 时会写入空标签，而系统同时存在名为“未分类”的默认标签。若不统一这两种状态，“未分类”文件夹的计数、筛选和批量整理会遗漏空标签文档。

## Goals / Non-Goals

**Goals:**

- 让左侧导航忠实呈现单层标签模型，并以文件夹语义提供筛选。
- 让具备编辑权限的用户可靠地持久化普通文件夹顺序。
- 让所有文档创建入口继承当前文件夹，并统一“未分类”的存储语义。
- 复用现有文档多选与批量标签更新能力完成批量归类。
- 保持普通用户只读导航、投稿用户上传、管理员/编辑者整理的权限边界。

**Non-Goals:**

- 不引入父子文件夹、文件夹路径或多标签文档。
- 不支持将文档拖拽到文件夹。
- 不支持跨分页选择全部筛选结果。
- 不改造 FAQ 标签管理界面。
- 不引入新的拖拽依赖。

## Decisions

### 1. 保留标签领域模型，仅改变文档页面的文件夹呈现

前端直接按 API 返回的 `sort_order` 渲染标签，不再拆分标签名称，也不再生成知识库根节点、层级编号或左侧文档子节点。固定的“全部文档”位于首行；“未分类”紧随其后；其他标签显示文件夹图标、名称、文档数和按权限出现的菜单。

选择文件夹只更新右侧列表的 `tag_id` 筛选。“全部文档”清除筛选。这样不需要新增父子字段或迁移标签名称，已有 `1.1-子类` 等名称将作为完整文件夹名保留。

### 2. 原子化保存完整的普通文件夹顺序

新增知识库范围内的重排端点，接收按目标顺序排列的普通标签 ID。服务层校验调用者至少具备编辑权限、ID 不重复、全部属于当前知识库，并且请求集合与当前普通标签集合一致；随后在事务中写入连续 `sort_order`。固定的“未分类”不参与请求并保持最前。

选择完整序列而不是逐项更新，是为了避免拖拽产生多次请求、部分成功或并发下的重复排序值。前端使用原生 HTML5 拖放，仅在普通文件夹和 `canEdit` 为真时启用；失败时恢复服务端顺序并提示。

标签导航在进入知识库时一次请求最多加载 1000 个未筛选标签，搜索仅在已加载集合中本地过滤，并移除“加载更多”。这是现有分页边界允许的最大值，也保证常规知识库的拖拽集合完整；若返回 `total` 超过已加载数量，则禁用拖拽并提示无法在不完整集合上排序。

### 3. 将“未分类”统一为真实默认标签

文档创建服务在未提供 `tag_id` 时查找或创建当前知识库的“未分类”标签，并写入其 UUID；所有上传入口仍可显式传入当前普通文件夹 ID。PostgreSQL 与 SQLite 两套迁移链均增加对应数据迁移，将已有空或 `NULL tag_id` 的文档及其块/索引元数据归入对应知识库的“未分类”标签，消除两种未分类状态。

“全部文档”和“未分类”上下文下创建文档时，前端不传普通文件夹 ID，由服务端统一解析为默认标签。普通文件夹上下文则传入该文件夹 ID。右侧上传区显示当前目标文件夹名称。

### 4. 在现有批量栏扩展“移动到文件夹”动作

复用当前可勾选行、`selectedIds` 和 `PUT /api/v1/knowledge/tags`。批量栏新增文件夹下拉操作，选择目标后把所选文档 ID 映射到目标标签 ID 并一次提交。只有 `canEdit` 为真时显示；目标列表排除当前文件夹，并排除“全部文档”虚拟入口。

移动成功后清空已移动项选择、重新加载右侧列表和标签计数；失败则保留选择，便于重试。移动是可逆分类操作，当前已加载项不额外弹确认框。

### 5. 权限继续复用现有知识库能力判断

所有用户均可点击文件夹筛选。普通投稿用户上传时继承当前文件夹，但不能拖拽排序、修改文件夹或批量移动已有文档。重排后端端点使用与标签更新相同的编辑权限校验，批量归类继续使用文档批量标签更新端点的现有授权。

## Risks / Trade-offs

- [风险] 当前工作区的 `KnowledgeBase.vue` 和批量操作组件已有未提交改动 → 仅修改文件夹树和批量归类相关片段，应用后按局部 diff 复查，避免覆盖现有治理功能。
- [风险] 浏览器原生拖放在触屏设备上体验有限 → 本次需求面向桌面管理页面，不新增依赖；触屏仍可查看和筛选。
- [风险] 超过 1000 个标签时无法取得完整排序集合 → 检测 `total` 并禁用排序，不发送不完整重排请求。
- [风险] 默认标签回填会更新存量数据且无法无损推断原空标签记录 → 迁移只处理空标签记录并按知识库复用或创建唯一“未分类”标签；回滚保留已归类数据，避免破坏用户随后进行的分类操作。
- [风险] 文件夹名称“未分类”由用户手工创建或重命名可能破坏固定语义 → 服务层继续依赖知识库内名称唯一约束，并禁止重命名或删除默认标签的管理入口；后端补充相同保护。

## Migration Plan

1. 部署数据库迁移，确保每个存在空标签文档的知识库都有唯一“未分类”标签，并回填关联。
2. 部署后端默认标签解析和文件夹重排端点。
3. 部署前端单层文件夹导航、上传目标提示和批量归类。
4. 回滚前端不会影响既有标签数据；回滚后端时保留已归类文档也可被旧版本读取。数据库 down 迁移为无损空操作并说明数据归一化不可逆，不清空任何文档标签。
