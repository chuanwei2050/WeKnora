## Context

现有 `internal/datasource/connector/feishu` 实现的是“飞书 → WeKnora”拉取，已经具备企业自建应用认证、知识空间枚举、节点遍历、导出下载和增量游标，但 `datasource.Connector` 的语义、持久化和调度均以外部系统为源，不能安全地反向复用为发布器。

目标交互位于编辑态 `KnowledgeBaseEditorModal.vue`：左侧新增“同步飞书”，右侧填写应用凭据，点击“获取知识空间”后选择目标知识空间与同步位置，再手动点击同步。飞书知识库的正常模型是 Wiki 页面树而非普通文件夹树；新版文档支持 File Block 和素材替换，因此每条 WeKnora 知识使用稳定 `docx` 页面承载原始附件，比每次重新导入并替换 Wiki 节点更能保持链接和用户协作内容。

外部 API 具有双重权限校验、异步操作和频率限制。配置包含敏感的 `app_secret`，同步还跨越数据库、对象存储、任务队列和飞书多个 API，必须具备明确的边界校验、幂等映射和部分失败恢复能力。

## Goals / Non-Goals

**Goals:**

- 在知识库设置内完成飞书发布配置、知识空间与页面树选择、同步前实时联通性及目标归属校验、手动同步和结果查看。
- 将目录映射为飞书导航页面，将每条源知识映射为稳定页面、原始附件和受控可检索正文，并保持原始文件保真。
- 通过快照、内容哈希和持久映射只执行必要变更，重复操作不产生重复节点。
- 仅修改同步器拥有的元信息块和附件块，保持页面链接及用户自定义区域稳定。
- 在多租户边界内安全保存凭据、限制权限并提供可诊断但不泄密的运行结果。

**Non-Goals:**

- 定时、Webhook 或内容变更自动同步。
- 飞书侧内容回写、双向冲突合并或以飞书为权威源。
- 将 Word、Excel、PowerPoint 自动转换成飞书在线文档、表格或幻灯片。
- 将解析分块发布为独立页面、发布 FAQ 知识库、生成式 Wiki 页面或知识图谱产物。
- 在一期提供多个飞书目标、跨租户共享配置或永久删除远端页面。

## Decisions

### 1. 新建发布目标领域，不反转 DataSource Connector

新增知识库级 `FeishuPublishConfig`、`FeishuPublishRun` 和 `FeishuPublishMapping`，并在飞书客户端中复用认证与受控 HTTP transport，扩展写 API。发布服务以 WeKnora 为源、飞书为目标，和现有拉取数据源保持独立路由、权限与任务类型。

备选方案是给 `datasource.Connector` 增加 Push 方法，但这会让所有 Connector 承担无意义的可选能力，并混淆来源删除与目标归档语义，因此不采用。

### 2. 配置和同步位于知识库设置的独立入口

“同步飞书”仅在已有文档型知识库的编辑模式显示。第一段只展示 `app_id`、`app_secret` 和“获取知识空间”按钮。endpoint 由服务器固定为官方地址，知识库管理员不能提交或覆盖 URL。已保存密钥只返回 `configured=true`，不回传明文；`app_id` 未变化时留空表示由后端沿用原密钥，修改 `app_id` 后必须重新填写密钥。

目标知识空间下拉框和同步位置树选择器初始置灰。点击“获取知识空间”时，后端使用当前表单凭据完成结构校验、换取 token 并列出应用可访问的 Wiki 空间；成功后启用知识空间下拉框。用户选择空间后，前端按需调用节点列表 API，懒加载可作为容器的页面树并启用“同步位置”；同步位置默认是知识空间根节点。UI 只展示空间名和页面标题，`space_id`、`node_token` 仅作为选项值传输和保存，不要求用户填写。

当 `app_id` 或 `app_secret` 变化时，前端立即清除本次获取状态并重新置灰目标控件，防止沿用旧凭据取得的空间和节点。切换知识空间时同步清空旧父节点选择。没有可访问空间时保持控件禁用，并提示将应用加入知识空间。

页面不显示独立“测试连接”。“获取知识空间”承担凭据和基础可访问性校验；点击“预览同步”时以后端收到的当前表单和选中目标为准，再次换取 token、确认空间、父节点及其归属。预览只保存在当前交互中；管理员确认时后端再次校验目标并在事务内保存加密配置、快照和运行记录，之后交给现有异步任务机制执行。无法通过只读接口确认的写权限由任务初始化步骤验证。

进入已有配置时显示已保存目标的完整面包屑、上次连接状态和最近运行，不要求先重新获取空间才能理解当前绑定。飞书页签隐藏弹窗通用“保存配置”按钮，只提供“关闭”“获取知识空间”“预览同步”和“解除绑定”；存在未提交表单变更时关闭或切换页签必须确认。密钥字段支持显隐切换，已保存密钥显示“已配置”而非伪装成可编辑掩码值，字段错误就近展示。

空间和页面树支持分页懒加载、面包屑与完整路径；“知识空间根目录”是明确的可选项。长任务关闭弹窗后继续执行，重新打开时恢复当前阶段和结果。部分失败提供“查看失败项”，再次执行普通同步即可跳过成功项；成功后提供“在飞书中打开”。页面树搜索延后到确有大空间使用反馈时再实现。

### 3. 获取状态与同步预检使用不同的明确状态

空间获取状态采用有判别字段的模型：`idle`、`loading`、`loaded`、`failed`；目标选择采用 `disabled`、`space_selected`、`location_selected`；同步运行采用 `queued`、`running`、`partial`、`succeeded`、`failed`。外部 JSON 在 HTTP client 边界解析为类型化结果，业务层不接收 `map[string]any`。

权限预检至少验证：凭据有效、目标空间存在且应用可访问、目标父节点属于该空间且可见。若飞书没有只读的完整写权限探测接口，首个实际写操作负责确认创建 Wiki 节点、编辑 Docx 和上传素材权限；失败时任务停止在目标初始化阶段并返回明确指引，不额外创建权限探针。

### 4. 稳定页面承载原始附件和可检索正文

根节点下创建一个 WeKnora 托管首页；每个目录创建 `docx` 导航页面，每条知识创建 `docx` 知识页面。知识页的托管区包含同步器标识、源文件名、最后同步时间、内容摘要、按源顺序拼接且有长度/块数上限的“可检索正文”和一个 File Block；原始文件上传到该块并始终作为权威载体。可检索正文只能取自快照锁定版本的已发布解析文本，不调用生成模型、不创建独立分块页面，并在截断或无可用文本时显式提示。映射保存 `space_id`、`node_token`、`obj_token`、元信息块 ID、正文块 ID 集合、文件块 ID、远端素材 token、源哈希、正文哈希和源版本。

更新时上传新素材并对已记录 File Block 执行附件替换，同时只替换同步器拥有的正文块，成功后再提交映射；不清空整页。目录或标题变化通过 Wiki 节点移动/标题更新处理。用户添加的其它块不属于托管集合，不读取为源、不覆盖、不回写。真实租户验收需记录普通搜索和知识问答对正文的实际表现，但附件上传成功不等同于检索承诺。

备选方案“原文件直接作为 Wiki 节点”更接近文件盘，且创建文件节点需要先上传/导入云空间再异步迁入，更新常导致节点身份变化；“转换为飞书原生文档”又不能保证原文件保真，均不作为一期默认。

### 5. 手动触发先预览、确认后增量落地

点击“预览同步”后，后端完成实时预检并基于当前源状态生成操作计划，返回创建、更新、移动、墓碑化、恢复、跳过、失败风险及预计上传量的汇总。预览不持久化；管理员确认时后端重新校验凭据和目标、重新生成快照与计划，若影响计数发生变化则返回新预览要求再次确认，否则在事务内保存当前配置、快照和运行记录。

快照包含全部当前 `KnowledgeDirectory`（包括空目录）、所有已映射 `Knowledge.ID` 的权威存在状态，以及可发布知识的不可变对象版本、租户限定对象键、长度、MIME、文件名、源版本、文件哈希、正文哈希和期望父节点。非软删除 `Knowledge` 才算存在；`EnableStatus` 必须启用、`ParseStatus` 必须成功；治理开启时只采用 `CurrentVersionID` 指向的已发布版本，不采用 `PendingVersionID`。对象缺失属于 `temporarily_ineligible` 而非删除。只有软删除/权威 tombstone 产生 `retire`，禁用、审核中、解析失败或暂时不可读取只产生 `skip_with_warning`，不得覆盖最后成功内容。

同一知识库同一目标同时最多一个活动运行。运行以 `(tenant_id, knowledge_base_id, target_id, snapshot_digest)` 作为幂等键；重复点击返回已有运行，不同快照遇到活动运行时返回冲突。运行固定 `space_id`、`parent_node_token`、`snapshot_id` 和执行所需配置副本，worker 不读取后续修改的配置或对象内容。

### 6. 删除采用墓碑化归档且失败不推进成功状态

每个 target 在选定位置下只有一个按稳定 target/KB ID 映射的托管首页，目录页、知识页和 `_KnowledgeMesh归档` 都位于该首页内，禁止按名称接管页面。权威删除的知识页先删除同步器拥有的附件块和可检索正文块，再写入不可检索旧正文的删除提示、把标题加上“[已归档]”并移入归档，映射标记为 `archived`；这保证旧源内容不再通过托管块参与搜索，同时保留稳定页面和用户自定义块。若任一步失败，保持映射为 active、报告失败并不得宣称删除已同步。相同源 ID 恢复时执行 `restore`，重建附件和正文、移回期望父节点并恢复源标题和稳定链接。带子节点目录按拓扑逆序归档，不调用永久删除。

飞书搜索索引可能延迟清理；任务以托管附件和正文块删除成功作为完成标准，并在运行结果中提示索引刷新可能延迟。真实租户验收记录实际延迟，超出可接受范围时再评估官方可恢复移除方案。

### 7. 安全、权限与可观测性集中在边界

配置 API、校验 API、触发 API 和运行查询 API 均从鉴权上下文解析 tenant/user，并验证知识库所有者或租户管理员权限，拒绝客户端声明 tenant。`app_secret` 使用现有加密基础设施保存，日志只记录配置 ID、运行 ID、飞书错误码和脱敏对象标识，不记录 secret、token、文件内容或完整飞书响应。

飞书 HTTP adapter 负责超时、响应大小、错误码解析、`429`/限频指数退避和请求级 telemetry；纯同步规划器只接收类型化本地快照与映射，输出类型化操作计划，便于无网络单元测试。

### 8. 复用现有异步任务并保持幂等

配置、快照和 `queued` 运行记录在同一数据库事务写入，再交给项目现有异步任务机制。任务投递失败时运行标记为 `failed` 并允许管理员再次同步；worker 依据运行 ID 和映射的期望哈希逐项幂等执行。状态归约固定为：系统级前置失败或零项成功且存在失败为 `failed`；至少一项成功且存在失败为 `partial`；全部完成为 `succeeded`。一期不新增通用 Outbox、worker lease、逐阶段 operation journal 或孤儿素材清理系统。

### 9. 远端对象逐项验证且不按名称接管

每次写操作必须验证本地链 `tenant → knowledge_base → target → mapping`，并从飞书确认 `space → managed home → node → obj` 仍可用。手动同步以 WeKnora 为权威：标题/父节点漂移改回期望值，托管块缺失则重建；远端节点删除或不在目标空间时重建页面并更新映射。禁止按标题认领任意无关页面；用户在非托管区域添加的内容不被删除。

源端结构权威。一期通过手动一键同步覆盖远端结构漂移（改名、移动、页面删除），不提供定时/Webhook 自动同步，也不做双向冲突合并。

### 10. 目标变更采用受限语义

首次成功同步后，`space_id` 被锁定，一期禁止直接切换知识空间；需要跨空间迁移时必须先解除目标，属于后续能力。同一空间内更改同步位置时，UI 二次确认，执行器只移动整个托管首页而非逐项重建。target identity 不因同空间父节点变化而改变。

一期不提供“停用同步”，因为同步只能手动触发。解除绑定只允许在没有活动运行时执行：二次确认其“不删除飞书内容、后续不再维护”的影响后删除当前配置中的密钥和目标，保留映射与运行历史供审计；解除后可重新绑定任意空间，但旧飞书内容不会自动迁移或接管。

### 11. 原始文件读取抵抗 TOCTOU 和资源滥用

worker 只能从 snapshot 指定的租户限定不可变对象版本流式读取，读取前后核对 tenant、对象版本、长度和 digest。禁止从知识元数据提供的任意 URL 下载，禁止自动跟随对象重定向；文件名移除控制字符与路径分隔符，大小、类型和流式字节数在边界限制。压缩文件只作为不解包附件传输，避免压缩炸弹。

### 12. 敏感接口和日志采用纵深防护

获取空间、节点和同步接口复用现有同源 CSRF/Origin 防护和鉴权中间件，服务端幂等键防止重复运行；对凭据失败和资源发现使用现有限流机制。secret 只在请求体内短暂存在，不进入 URL、浏览器持久化、APM body capture、通用请求日志或队列 payload。

日志使用字段允许列表，只记录内部错误码、run/config ID 和不可逆脱敏标识；清除 Authorization、secret、token、endpoint query、文件名、标题、外部 message、响应体与堆栈中的敏感值。逐项结果按 tenant 鉴权并设置保留期。

### 13. 回环重叠采用硬阻止

同一 tenant/knowledge base 的发布目标若与现有飞书拉取数据源的空间或托管根重叠，系统必须拒绝配置和同步，不能由用户忽略。导入侧再按持久化 node/object ID 范围和签名机器标记排除发布内容，用户可编辑文本不是安全边界。

## Risks / Trade-offs

- [飞书未公开保证附件正文可检索] → 原始附件之外写入同版本受控正文；真实租户记录普通搜索和知识问答表现，产品文案不承诺附件本身可检索。
- [同空间归档页的索引清理可能延迟] → 删除时先清空托管附件和正文并写墓碑提示，运行结果说明飞书索引刷新可能延迟，真实租户记录实际范围。
- [同步确认前源内容发生变化] → 确认时重新校验并重新计算影响；计数变化则展示新预览要求再次确认。
- [飞书没有完全无副作用的写能力探测] → 预览验证可读权限，实际任务的目标初始化步骤验证写权限；失败时停止并给出授权指引，不创建额外探针。
- [File Block 替换或素材生命周期与预期不一致] → 真实租户验证替换后下载内容、页面链接、旧素材回收和权限；不满足时退化为重建托管附件块但保持页面节点不变。
- [用户删除或移动托管块 / 远端改名移动删页] → 下次手动同步以 WeKnora 覆盖：重建托管块或页面，改回标题与父节点；不按标题接管无关页面，不删除用户非托管备注。
- [超大文件、文件类型或飞书配额不支持] → 预检大小与类型；逐项失败并保留上次成功附件，运行标记 `partial`。
- [目录同名、重命名或循环映射错误] → 使用 WeKnora UUID 作为身份，名称仅作展示；同步规划器先验证无环树和父节点存在。
- [手动同步过程中源文件变化] → 使用不可变快照和确定的版本/哈希；变化留待下次手动同步。
- [页面允许用户编辑会产生认知冲突] → 页面展示“附件由 WeKnora 托管”，只保护托管块，允许用户在非托管区域写备注但不回写。
- [现有飞书拉取源指向发布目标形成回环] → 同一知识库与空间/托管根重叠时硬阻止，签名来源标记和持久化远端 ID 过滤作为纵深防护。

## Migration Plan

1. 增加配置、映射与运行表，先部署为不可见能力；迁移不修改现有 DataSource 数据。
2. 扩展飞书写客户端并用隔离测试空间验证权限、File Block、托管正文搜索表现、附件替换、移动、墓碑化和限流，记录外部索引延迟。
3. 上线后端资源发现、预览/确认、解绑、运行查询 API 与异步任务，默认功能开关关闭。
4. 上线知识库设置入口，在内部租户灰度；以小型基线（≥40 篇）、深层目录（≥4 层）和重名节点知识库验收完整交互；不以 ≥100 篇压测或飞书检索 SLA 作为一期门禁。
5. 开启功能。回滚时关闭入口和任务消费；保留映射与飞书页面，不执行远端删除，后续恢复可继续同步。

## Open Questions

- 飞书套餐、素材大小和文件类型限制需要形成怎样的产品级上限及提示文案。
- 页面树节点数量较大时，前端分页懒加载的体验需要在真实大空间验证；搜索能力根据一期反馈决定，不得退化为要求用户手填 token。
