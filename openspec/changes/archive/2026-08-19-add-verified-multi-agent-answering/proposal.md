## Why

立项材料要求检索、推理、验证、反思 Agent 协作，并通过多模型互证提升答案准确性与稳定性。当前系统只有一个通用 ReAct 执行引擎；`builtin_agents.yaml` 中的 `reflection_enabled` 没有对应的持久化/运行时字段，工具执行后也没有事实与逻辑验证、失败回流和有界重生成闭环。

## What Changes

- 增加检索、推理、验证、反思四阶段的编排器及类型化阶段输入/输出，阶段失败可独立观测和降级。
- 支持主回答模型与一个或多个验证模型，分别执行事实对齐、逻辑一致性、引用支撑度和答案完整性检查；严格多模型按规范化的提供方、端点和模型身份判重。
- 汇总验证结论与置信度；未达阈值时把结构化问题反馈给反思阶段，并在有界次数内重新检索或生成。
- 达到重试上限仍不可信时输出不确定性说明和可核验依据，不把低置信答案伪装成确定事实。
- 对完整请求设置总耗时、模型调用次数、token 和并行度预算，预算耗尽时取消未完成工作并进入可审计的保守输出。
- 将 `reflection_enabled`、验证模型、阈值、最大反思次数和失败策略纳入真实配置契约。
- 接收问题复杂度和图谱推理路径作为可选输入；相关变更未启用时仍可基于现有 RAG 结果运行。
- 增加用户答案反馈入口，将纠错反馈保存为待审核项；采纳时只允许选择当前已启用的知识草稿、评测样例候选或改进工单去向，不存在可用下游时保持待审核，不自动发布知识或改写模型参数。

## Capabilities

### New Capabilities

- `verified-multi-agent-answering`: 分阶段多 Agent 编排、多模型验证、置信度汇总、有界反思纠错和人工反馈闭环。

### Modified Capabilities

无。

## Impact

- 后端：`internal/agent`、session service、model service、事件流、消息/反馈持久化及 tracing。
- 配置：CustomAgent 与内置 Agent 配置 schema、验证策略和模型选择。
- 前端：Agent 配置、验证摘要、置信度和反馈控件。
- 成本与延迟：仅对启用验证或复杂度策略要求的请求增加模型调用，并提供预算上限。
