## ADDED Requirements

### Requirement: 类型化的验证式回答阶段

系统必须（MUST）以类型化契约依次组织证据获取、草稿生成、验证、受限反思和最终回答，并在每个阶段保留输入输出的关联标识。

#### Scenario: 完成一次验证式回答

- **WHEN** 已启用验证式回答的智能体收到一个需要知识检索的问题
- **THEN** 系统生成可关联的证据包、草稿、验证报告和最终回答
- **AND** 最终回答中的引用可追溯到证据包中的来源

### Requirement: 多模型验证配置

系统必须（MUST）允许为事实、逻辑和引用验证角色配置模型，并在严格多模型模式下校验至少存在两个不同的规范化模型身份。模型身份 MUST 由协议/提供方、规范化基础端点、模型名称和版本确定，不得使用数据库记录 ID 冒充独立模型。

#### Scenario: 严格模式配置重复模型

- **WHEN** 管理员启用严格多模型模式但所有验证角色指向同一个模型身份
- **THEN** 系统拒绝保存或启用该配置
- **AND** 返回可操作的配置错误

#### Scenario: 两条模型记录指向同一服务

- **WHEN** 两条不同数据库记录具有相同的规范化提供方、端点、模型名称和版本
- **THEN** 系统在严格多模型校验中将它们视为同一模型身份
- **AND** 不把该配置标记为多模型共识

#### Scenario: 运行时验证模型不可用

- **WHEN** 一个验证模型在执行期间不可用且配置允许降级
- **THEN** 系统使用剩余验证能力继续执行
- **AND** 将本次结果明确标记为降级验证而非多模型共识

### Requirement: 多维声明级验证

系统必须（MUST）对草稿中的可验证声明执行事实一致性、逻辑一致性、引用支持度和回答完整性检查，并输出声明 ID、证据 ID、验证维度和严重程度。

#### Scenario: 引用不支持声明

- **WHEN** 引用验证器发现某个声明无法由其关联证据支持
- **THEN** 验证报告将该声明标记为引用问题
- **AND** 报告包含声明与证据的关联标识及严重程度

### Requirement: 确定性聚合与阈值

系统必须（MUST）按照可配置且可审计的权重与阈值聚合验证结果，产生通过、需要反思或保守回答三种决策之一。

#### Scenario: 验证结果低于反思阈值

- **WHEN** 聚合分数低于通过阈值但满足反思条件且仍有反思预算
- **THEN** 系统选择需要反思
- **AND** 记录使用的权重、阈值和各维度分数

### Requirement: 有界反思与恢复动作

系统必须（MUST）限制反思次数，且每轮只能执行补充检索、重写回答或停止作答中的显式动作；每次补检索或重写后必须重新验证。

#### Scenario: 补充检索后通过验证

- **WHEN** 首次验证发现证据不足且仍有反思预算
- **THEN** 系统执行一次补充检索并重写草稿
- **AND** 新草稿通过重新验证后才作为已验证回答输出

#### Scenario: 达到反思上限

- **WHEN** 系统达到配置的最大反思次数且回答仍未通过
- **THEN** 系统停止反思循环
- **AND** 不再发起新的模型或检索调用

### Requirement: 完整请求执行预算

系统必须（MUST）为每次验证式回答强制执行总墙钟耗时、模型调用次数、输入/输出 token 和并行模型调用数预算；所有检索、生成、验证和反思阶段共享该预算，阶段级限制不得绕过总上限。

#### Scenario: 总预算在验证阶段耗尽

- **WHEN** 已执行的检索和模型调用耗尽任一总预算且仍有验证或反思工作未开始
- **THEN** 系统不再启动新调用并取消可取消的未完成工作
- **AND** 按配置返回明确标记的降级或保守结果并记录耗尽的预算类型

#### Scenario: 客户端中断请求

- **WHEN** 客户端断开或请求上下文被取消
- **THEN** 系统将取消信号传播到仍在运行的检索和模型调用
- **AND** 不继续产生未计入预算的孤儿调用

### Requirement: 未验证草稿不可见

系统必须（MUST）将草稿正文、验证意见和反思重写限制在内部阶段，不得将未完成验证决策的正文作为用户可见聊天内容持久化或流式发送；只有最终验证回答或明确标记的保守回答可以成为消息正文。

#### Scenario: 草稿在验证后被重写

- **WHEN** 首个草稿已生成但验证器要求重写
- **THEN** 客户端只收到不包含草稿正文的阶段状态
- **AND** 消息记录与最终答案流仅包含验证决策后的正文

### Requirement: 低置信度安全回答

系统必须（MUST）在达到反思上限、关键验证器失败或可靠证据不足时，以明确的不确定性说明输出保守回答；无法支持核心结论时不得给出确定结论。

#### Scenario: 核心结论没有可靠证据

- **WHEN** 最终验证报告表明核心声明没有可用证据支持
- **THEN** 系统明确说明当前知识不足
- **AND** 不把未经支持的核心声明表述为事实

### Requirement: 配置真实生效并默认兼容

系统必须（MUST）在智能体配置类型、持久化和运行时中实现验证与反思字段；未启用的历史智能体必须继续使用原有回答流程。

#### Scenario: 历史智能体没有验证配置

- **WHEN** 系统加载一个迁移前创建且没有验证字段的智能体
- **THEN** 验证式回答默认为关闭
- **AND** 该智能体仍可按原流程回答

#### Scenario: 启用反思配置

- **WHEN** 管理员保存合法的验证模型、阈值和反思次数配置
- **THEN** 后续请求按照保存后的配置执行验证与反思
- **AND** 配置不再是仅解析但被运行时忽略的字段

### Requirement: 阶段事件与可观测性

系统必须（MUST）记录各阶段耗时、使用的模型身份、检索次数、验证分数、反思动作、降级原因和最终状态，同时不得记录或展示模型私有思维链。

#### Scenario: 管理员检查失败回答

- **WHEN** 管理员查看一次未通过验证的回答追踪
- **THEN** 系统展示阶段、分数、问题分类、引用和最终决策
- **AND** 不展示模型私有思维链原文

### Requirement: 用户反馈审核队列

系统必须（MUST）允许用户对最终回答评分并提交可选纠错说明，将反馈关联到回答版本并进入具有待审核、采纳和驳回状态的审核队列。采纳反馈时 MUST 从当前已注册可用的下游能力中显式选择知识草稿、评测样例候选或改进工单之一，并保留来源与审核链；任何候选均不得自动发布或直接改变生产行为。没有可用下游或所选下游已停用时 MUST 拒绝采纳并保持反馈为待审核。

#### Scenario: 用户提交纠错反馈

- **WHEN** 用户对一个回答提交负面评分和纠错说明
- **THEN** 系统创建关联该会话、消息和回答版本的待审核反馈
- **AND** 不直接修改知识库、提示词或模型配置

#### Scenario: 管理员采纳纠错反馈

- **WHEN** 知识治理能力已启用且有权限的管理员采纳一条纠错反馈并选择生成知识草稿
- **THEN** 系统创建关联反馈、回答版本、审核人和来源证据的待审核知识草稿
- **AND** 该草稿仍须通过知识治理审核后才能发布
- **AND** 重复提交同一采纳动作不会生成重复候选

#### Scenario: 所选改进去向不可用

- **WHEN** 管理员尝试把反馈采纳为知识草稿，但当前租户或知识库未启用知识治理能力
- **THEN** 系统拒绝该采纳动作并返回可操作的能力缺失说明
- **AND** 反馈保持待审核且不创建悬空候选

### Requirement: 权限边界保持不变

系统必须（MUST）确保检索、补检索、验证和反馈查看均继承现有用户、知识库和会话权限，不得因多阶段执行扩大数据访问范围。

#### Scenario: 反思请求补充检索

- **WHEN** 反思阶段对用户无权访问的知识库提出补充检索建议
- **THEN** 系统仅在原请求允许的知识库范围内执行检索
- **AND** 不向任何阶段返回越权证据
