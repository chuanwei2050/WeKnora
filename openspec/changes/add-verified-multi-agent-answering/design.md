## 背景

当前问答执行以单个 `AgentEngine` 的 ReAct 循环为主，检索、推理和作答主要由同一模型完成。内置智能体配置虽然出现了 `reflection_enabled`，但类型定义和运行时没有对应的反思执行链，也没有独立的事实、逻辑和引用验证阶段。因此，复杂问题可能在证据不足或推理冲突时直接输出答案，无法满足任务书提出的多智能体协作、多模型校验和反思纠错要求。

本变更在现有检索、模型调用和 Agent 能力之上增加可选的验证式回答编排，不替换基础聊天流程。它可以消费问题复杂度路由和多跳图谱检索结果，但不把这两个变更作为启用前提。

## 目标与非目标

### 目标

- 将检索、推理、验证和反思定义为边界清晰、可观测的执行阶段。
- 支持不同模型承担事实、逻辑和引用验证角色，并显式标记降级状态。
- 对验证失败的回答执行次数受限的补检索或重写，仍不合格时安全表达不确定性。
- 将用户评分和纠错意见进入人工审核队列，为后续知识治理和评测提供数据。
- 保持现有智能体默认行为兼容，验证式回答由配置显式启用。

### 非目标

- 不实现模型训练、在线参数更新或自动改写生产提示词。
- 不向用户或日志暴露模型的私有思维链。
- 不要求所有普通问题都调用多个模型。
- 不在本变更中实现问题复杂度分类或图谱多跳查询本身。

## 关键决策

### 1. 使用类型化协调器编排阶段

新增 `VerifiedAnswerCoordinator`，复用现有知识检索、Agent、模型和消息服务，按以下契约传递结果：

- `EvidenceBundle`：证据内容、来源、权限上下文和检索方式。
- `DraftAnswer`：回答正文、声明列表和声明到证据的引用关系。
- `ValidationReport`：逐声明问题、问题严重级别、验证维度和建议动作。
- `ReflectionPlan`：继续补检索、重写回答或停止并保守作答。
- `VerifiedAnswer`：最终正文、引用、置信状态和执行摘要。

阶段契约避免依赖不可解析的自由文本，并允许每一步独立测试和追踪。

### 2. 验证角色并行运行，模型身份可审计

事实、逻辑和引用验证器通过配置绑定模型。彼此独立的验证器可并行执行以控制延迟。模型身份由规范化后的协议/提供方、基础端点、模型名称和版本组成，不使用数据库记录 ID 判定独立性；指向同一端点与同一模型的重复配置只算一个身份。严格多模型模式要求至少两个不同的规范化模型身份；若配置或运行故障导致只剩一个验证模型，系统可以按策略终止或降级，但必须在结果和追踪中标记 `degraded`，不得冒充多模型共识。

### 3. 验证输出采用结构化问题和确定性聚合

验证器输出声明 ID、关联证据 ID、维度、严重程度和建议，不以一段评语代替结果。系统按配置权重聚合事实一致性、逻辑一致性、引用支持度和完整性分数，并使用固定阈值决定通过、反思或保守回答。模型生成解释可以辅助人工审核，但不参与未定义的隐式决策。

### 4. 反思循环有硬性上限

协调器根据 `ReflectionPlan` 最多执行配置次数的补检索或重写，默认一次、硬上限两次。每轮都重新验证。达到上限仍未通过时，输出带不确定性说明和已有可靠引用的保守回答；证据不足时明确拒绝给出确定结论。

### 5. 完整请求受总预算约束

除反思次数外，每次验证式回答还必须具有总墙钟耗时、模型调用次数、输入/输出 token 和并行模型调用数上限。协调器在单一预算对象中原子预留与结算资源，并向所有子阶段传递取消信号；任何总预算耗尽后都不得再启动新检索或模型调用，未完成调用应被取消，并按策略输出降级或保守结果。阶段级超时只能缩小总预算，不能延长它。

### 6. 草稿仅在内部流转

`DraftAnswer`、验证意见和反思重写内容属于内部阶段产物，不作为聊天正文持久化，也不通过面向用户的答案事件流输出。客户端可以收到不含草稿正文的阶段状态；只有完成验证决策后的 `VerifiedAnswer` 或明确标记的保守回答可以作为最终正文保存和展示，避免用户看到随后被判错或被替换的内容。

### 7. 配置进入实际类型和运行时

在 `CustomAgentConfig` 和运行时 `AgentConfig` 中增加验证与反思配置，包括启用开关、验证模型、阈值、最大反思次数和降级策略。现有 `reflection_enabled` 配置将映射到新字段；未配置时默认关闭，保持历史智能体行为不变。

### 8. 用户反馈进入受控改进流程

反馈记录关联会话、消息、回答版本、评分和可选纠错文本，并具有待审核、采纳、驳回状态。反馈不会直接修改知识库、提示词或模型配置；采纳动作由有权限的管理员完成，并且必须显式选择一个当前可用的下游：知识治理已启用时可以生成带来源的知识草稿，评测治理已启用时可以生成评测样例候选，配置了改进工单 repository 时可以生成改进工单。服务端从能力注册表派生可选去向并在提交时再次校验；没有可用下游或选中能力已停用时拒绝采纳且反馈保持待审核，不创建悬空记录。

生成物保留反馈、回答版本、审核人和处置结果关联，知识草稿仍需知识治理审核后才能发布，评测样例候选仍需人工确认后才能进入正式数据集；重复采纳必须幂等。

### 9. 只记录可解释执行摘要

追踪记录阶段耗时、模型身份、检索次数、验证分数、问题类别、反思动作和最终状态。对外可展示“进行了哪些检查”和引用依据，但不保存或展示模型私有思维链。

## 集成边界

- 问题复杂度变更只负责输出分类与策略提示，本变更负责在自身配置和总预算内决定是否执行验证及反思。
- 图谱检索变更只提供有权限且可追溯的图证据，本变更将其作为 `EvidenceBundle` 的一种来源，不自行生成图路径。
- 知识治理变更负责知识草稿审核与发布；只有其能力注册为可用时，本变更才允许创建反馈驱动的知识草稿候选和来源关联。
- 验收基准变更负责样例审批、指标计算和发布门禁；只有其能力注册为可用时，本变更才允许创建评测样例候选。
- 私有化部署变更负责模型端点是否可用及离线策略，本变更仅按规范化模型身份和调用预算使用已注册模型。

## 数据与接口影响

- 新增验证配置、规范化模型身份、总预算、阶段事件、验证报告、回答反馈及改进候选的数据结构。
- 扩展智能体保存与读取接口，使配置能够从 YAML、数据库和 API 一致生效。
- 流式聊天事件增加不含草稿正文的验证状态和最终置信状态；旧客户端可忽略未知事件。
- 新增反馈提交、管理员审核和受控候选生成接口，沿用现有会话与知识库权限体系。

## 风险与权衡

- 多模型验证会增加耗时和调用成本，因此默认关闭，并允许按问题路由启用。
- 验证模型也可能产生错误；结构化证据检查、模型身份审计和人工反馈用于降低而非消除该风险。
- 反思可能重复检索相同证据；执行预算和证据去重用于限制浪费。
- 多阶段任务可能在客户端断开后继续消耗资源；总预算、取消传播和幂等结算用于限制孤儿调用。
- 严格阈值可能增加保守回答比例；阈值应通过验收数据集校准，而不是在代码中隐藏调整。

## 迁移方案

1. 增加配置字段和持久化迁移，默认关闭验证式回答。
2. 实现阶段契约、规范化模型身份、总预算、验证器和协调器，并接入只输出最终正文的聊天流可选分支。
3. 将已有 `reflection_enabled` 配置迁移到新字段并记录不完整配置告警。
4. 增加反馈记录、审核接口、受控改进候选和管理入口。
5. 使用固定评测样本校准阈值后，再按智能体逐步启用。

## 待确认问题

- 首批部署可用的独立验证模型数量和调用预算需要由部署方确认。
- 反馈审核是否与知识治理审核使用同一角色，待权限模型实现时统一决定。

## 补充设计决策

### 10. 反思补检索必须重新进入受限检索服务

`ReflectionPlan` 的 `retrieve` 动作不能复用首轮 evidence bundle 作为结果。协调器必须根据验证报告生成结构化的补检索请求，并复用原会话、知识库、知识版本、工具权限、图谱使用决策和总预算执行一次受限检索；新增证据与原证据按稳定 ID 去重，再生成新草稿并重新验证。

补检索没有命中时必须记录 `no_new_evidence`，不能通过改写措辞伪造验证通过。补检索查询必须禁止扩大知识库、网络、工具或版本范围。

### 11. 验证与复杂度路由的边界

验证协调器消费路由提供的动作和预算，不自行重新分类。只有真正进入 `verified_agent` 的执行分支才使用 Agent 工具循环；普通 RAG 的验证后处理继续作为独立兼容路径，并在遥测中区分 `verified_rag_postcheck` 与 `verified_agent`。
