## Why

用户常用特殊资质简称提问，而知识库内容通常使用标准名称，导致向量、Elasticsearch、SQL、知识图谱、Wiki 和 FAQ 等检索渠道可能漏召回。简称识别应在检索路由之前统一完成，避免每个渠道重复实现。

## What Changes

- 在知识库设置中增加“特殊资质简称”配置，维护简称与标准名称的对应关系。
- 在检索路由前统一处理查询：命中简称时保留原问题并追加标准名称，未命中时保持原问题不变。
- 所有下游知识库检索渠道统一消费处理后的查询，包括向量、Elasticsearch、SQL、知识图谱、Wiki 和 FAQ。
- 同一知识库内不允许配置重复简称，配置更新后对新查询生效。
- 不进行模型训练或微调，不引入资质编码、复杂实体体系或自动学习机制。

## Capabilities

### New Capabilities

- `knowledge-base-qualification-aliases`: 定义知识库简称配置、校验、统一查询扩展及所有下游知识库检索渠道的消费行为。

### Modified Capabilities

- `shared-retrieval-kernel`: 普通 RAG 与 Agent RAG 在路由前复用相同的简称查询预处理结果。

## Impact

- 数据库：知识库记录增加 JSON 简称配置字段及 migration。
- 后端：知识库配置读写校验和路由前查询预处理。
- 检索：现有向量、ES、SQL、图谱、Wiki 与 FAQ 流程接收统一扩展后的查询。
- 前端：知识库设置页新增简称配置编辑区域。
- 测试：配置持久化、重复校验、查询扩展、跨知识库范围和各检索入口回归测试。
