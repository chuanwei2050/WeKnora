## Why

立项材料要求知识库覆盖测评专业知识、标准、体系与项目经验，并具备增量更新、版本管理和人工审核能力。当前项目已有通用文档入库、标签和可配置图谱抽取，但知识记录缺少软件测评领域语义、来源权威性、有效期、可追溯版本和发布审核，无法可靠处理标准换版与企业经验沉淀。

## What Changes

- 提供可直接启用的软件测评领域知识模型，明确标准知识、基础理论知识、企业内部体系知识、项目/专家经验知识四层来源，并覆盖测评对象、质量特性、测试方法、工具、指标、缺陷和结论等核心概念及关系。
- 为知识来源增加类别、标准编号、版本、发布/生效/失效日期、权威等级等结构化元数据，并在引用中展示关键版本信息。
- 建立知识版本快照与差异记录；重复同步或重新解析不得静默覆盖既有已发布版本。
- 建立可穷举的知识版本生命周期，覆盖草稿、待审核、已批准、索引中、预约生效、当前生效、发布失败、已替代、已驳回和已失效；只有 `active` 版本进入生产检索和图谱查询。
- 支持审核后的发布、驳回和回滚，并保留操作者、时间与意见记录。
- 对既有知识执行兼容迁移，保持当前可检索行为，不引入破坏性变更。

## Capabilities

### New Capabilities

- `software-testing-knowledge-governance`: 软件测评领域知识模型、来源与有效性元数据、版本历史、审核发布及检索可见性规则。

### Modified Capabilities

无。

## Impact

- 后端：`internal/types`、数据库迁移、knowledge repository/service/handler、数据源同步和索引任务。
- 前端：知识详情、版本对比、审核队列、状态筛选及引用展示。
- 检索与图谱：索引任务需按发布状态和有效期过滤，并保留版本来源。
- 部署：PostgreSQL 与 SQLite 均需提供等价迁移；现有 API 默认行为保持兼容。
