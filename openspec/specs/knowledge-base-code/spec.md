# knowledge-base-code Specification

## Purpose
定义知识库人工业务编码的配置、格式校验、租户内唯一性、大小写处理与查询解析语义，并约束管理界面的字段展示和输入提示。

## Requirements
### Requirement: 知识库支持人工业务编码
系统 SHALL 允许具备知识库编辑权限的用户为知识库配置可选业务编码；非空编码 MUST 仅包含英文字母、数字、`-` 和 `_`，长度 MUST 为 1–64 个字符，并在同一租户内按大小写不敏感方式唯一。系统 SHALL 保留用户输入的显示大小写，但 MUST 使用统一规范化键执行判重和查找。

#### Scenario: 配置有效编码
- **WHEN** 编辑者在知识库名称下方输入 `RAG_KB-2026` 并保存
- **THEN** 系统保存该编码并在重新打开配置时原样显示

#### Scenario: 不配置编码
- **WHEN** 编辑者将知识库编码留空并保存
- **THEN** 系统允许保存且将编码记录为未配置

#### Scenario: 输入非法字符
- **WHEN** 编辑者输入包含空格、中文、斜杠或其他非允许字符的编码
- **THEN** 前端阻止提交并提示编码格式要求
- **AND** 服务端拒绝任何绕过前端的非法编码

#### Scenario: 租户内编码冲突
- **WHEN** 同一租户内另一知识库已使用相同或仅大小写不同的非空编码
- **THEN** 系统拒绝创建或更新并返回编码冲突错误

#### Scenario: 不同租户使用相同编码
- **WHEN** 两个不同租户分别为知识库配置相同编码
- **THEN** 系统允许保存且各自只能在所属租户范围内解析

#### Scenario: 使用不同大小写查询编码
- **WHEN** 知识库保存的编码为 `Rag_KB-1` 且调用方查询 `rag_kb-1`
- **THEN** 系统解析到同一知识库
- **AND** 配置界面仍显示原始值 `Rag_KB-1`

#### Scenario: 清除已有编码
- **WHEN** 编辑者清空已配置的知识库编码并保存
- **THEN** 系统将该知识库编码恢复为未配置

### Requirement: 知识库配置展示编码字段
知识库设置的基本信息页面 SHALL 在“知识库名称”下方显示“知识库编码”输入框，其输入提示 MUST 为“用于筛选知识库（可选）”。

#### Scenario: 打开知识库基本配置
- **WHEN** 编辑者打开知识库设置的基本信息页面
- **THEN** “知识库编码”位于“知识库名称”之后、“知识库描述”之前
- **AND** 输入框显示“用于筛选知识库（可选）”提示
