## 1. 总体架构

```text
业务系统后端                         用户浏览器                         独立 FinOpsSys
client_id + client_secret ──换 token──────────────────────────────────►│
识别当前业务用户 ───────────申请 ticket────────────────────────────────►│
                                      │◄──一次性 ticket─────────────────┘
                                      ├── 打开 FinOpsSys 前端 iframe / Widget
                                      ├── iframe / Widget 兑换会话（Cookie 或 Bearer）
                                      └── 访问 FinOpsSys Integration / 业务 API
```

这里有两个不能混用的概念：

- `parent_origin`：业务系统宿主页面的 Origin，只用于 `postMessage` 安全校验。
- `bootstrap.origin` / `allowed_origins`：浏览器实际加载 FinOpsSys 前端、并发起 API 请求时的 **页面 Origin**，用于票据、Cookie/Bearer 与 CSRF 绑定。

### 1.1 两种前端部署模式

| 模式 | 适用场景 | `WEKNORA_FRONTEND_URL` | `allowed_origins` / bootstrap `origin` |
| --- | --- | --- | --- |
| **跨域直连** | FinOpsSys 有独立公网/HTTPS Origin，且与宿主同为公网可达 | 独立 FinOpsSys 前端地址 | 填 **FinOpsSys 前端 Origin**；宿主 Origin 只用于 `parent_origin` / `FRAME_ANCESTORS` |
| **同域反代** | 宿主为公网入口，FinOpsSys 仅内网端口；或公网页不能拉内网资源（Chrome Private Network Access） | **等于宿主 Origin**（由宿主反代 `/widget`、`/knowledge`） | 填 **宿主 Origin**（与浏览器页面 Origin 一致） |

跨域直连是默认推荐（独立 HTTPS 域名）。同域反代用于公司 HTTP 入口、无独立公网端口、或公网页无法直连内网 FinOpsSys 的场景。

同域反代时必须同时满足：

1. 宿主网关把 `/widget/*`、`/knowledge/*` 反代到 FinOpsSys 前端；API 由 FinOpsSys nginx 的 `/knowledge/api/`、`/knowledge/files` 再转到 App，避免与宿主自有 `/api/*` 冲突。
2. 宿主 CSP **不得**再给 `/widget`、`/knowledge` 响应叠加 `frame-ancestors 'none'`（否则 iframe 被拦）。
3. FinOpsSys `FRAME_ANCESTORS` 仍须包含宿主 Origin。
4. 官方 frontend 镜像会双构建：独立站 `base=/`，嵌入站 `base=/knowledge/embed/`。宿主 iframe **必须**使用 `/knowledge/embed/...` 路径，不能使用 `/knowledge/platform/...`（后者会落到独立站产物，静态资源路径与反代规则易冲突）。
5. 跨站 Cookie 不可靠时，使用 exchange 返回的 `session_token`（`Authorization: Bearer`）；同站 Cookie 仍可兼容。

禁止：公网宿主页面直接引用内网地址（如 `http://192.168.x.x:8089/widget/...`）。浏览器会按 Private Network Access 拦截。

必须遵守以下边界：

- 一个业务项目对应一个 integration client，client 在服务端固定绑定一个 FinOpsSys 租户。
- `client_secret` 和 service token 只能保存在业务系统后端，不能进入浏览器、URL、日志或前端配置。
- 租户 API Key 只可用于管理员侧确认或初始化租户，不作为外挂页面的运行期凭证。
- 浏览器只接收最长 60 秒、仅能使用一次且绑定 Origin 的 bootstrap ticket。
- 页面和 API 权限最终取 client 知识库访问模式、用户权限和租户边界的交集。

平台管理员也可以在“平台管理 → 租户管理”的操作列点击“创建接入”。

填写：

- 接入项目名称；
- 身份提供方 ID；
- 第三方项目 Origin；
- 要绑定的有效 `tenant_admin`。

系统会创建或复用身份源、创建租户级 Client；`client_secret` 会加密保存，平台管理员可在“接入信息”中随时查看并复制完整环境变量。升级前已创建、尚无可回看密文的 Client，需先“重新生成密钥”一次。

一键创建里的「第三方项目 Origin」在跨域直连时填 FinOpsSys 前端 Origin；同域反代时填宿主 Origin。

一键创建输出中的 `WEKNORA_INTEGRATION_TENANT_ID` 必须由第三方项目填写自己的内部租户或工作区 ID；它用于外部身份映射，不是 FinOpsSys 的数字租户 ID。FinOpsSys 数字租户 ID 已固化在 Client 中，第三方不能通过请求切换。

## 2. 项目和账号映射

### 2.1 创建身份源

```http
POST /api/v1/admin/integration-identity-providers
Authorization: Bearer <平台管理员令牌>
Content-Type: application/json

{"id":"erp","name":"ERP 用户中心"}
```

### 2.2 创建项目 client

如果项目允许外部管理员进入，必须在 `administrator_user_id` 显式指定一个现有、有效、同租户的 `tenant_admin`。系统不会自动选择或创建管理员。

```http
POST /api/v1/admin/integration-clients
Authorization: Bearer <平台管理员令牌>
Content-Type: application/json

{
  "id": "erp-project-a",
  "name": "ERP 项目 A",
  "tenant_id": 10000,
  "identity_provider_id": "erp",
  "administrator_user_id": "<已有租户管理员用户ID>",
  "scopes": [
    "kb:list", "rag:search", "table:analyze", "chat:read", "chat:write",
    "knowledge:read", "knowledge:write", "file:read"
  ],
  "knowledge_base_access_mode": "all",
  "knowledge_base_ids": [],
  "allowed_origins": ["https://weknora.example.com"],
  "role_mappings": {
    "project_admin": "tenant_admin",
    "project_user": "member"
  },
  "max_role": "tenant_admin"
}
```

上例 `allowed_origins` 按跨域直连填写 FinOpsSys 前端 Origin；同域反代时改为宿主 Origin（见 §1.1）。

知识库授权有两种显式模式：

| 模式 | `knowledge_base_ids` | 用途 |
| --- | --- | --- |
| `all` | 必须为空 | 绑定租户当前及未来创建的全部知识库，适合在外挂管理页持续新建、设置和上传文档 |
| `selected` | 指定知识库 ID | 固定白名单，适合只允许第三方项目访问部分既有知识库 |

省略 `knowledge_base_access_mode` 时按 `selected` 处理，以保持已有 Client 的权限不扩大。`all` 会在认证边界按 Client 固定租户实时解析当前知识库，再与用户权限求交集；新建知识库后当前有效会话即可继续管理，同时仍不会访问其他租户知识库。

已有 Integration Client 增加表格分析权限时，不需要重建 Client 或更换密钥：

```http
PUT /api/v1/admin/integration-clients/<client_id>/scopes
Authorization: Bearer <平台管理员令牌>
Content-Type: application/json

{"scopes":["kb:list","knowledge:read","rag:search","table:analyze","chat:read","chat:write"]}
```

更新 scope 会撤销该 Client 的现有会话；调用方应使用原 `client_id/client_secret` 重新申请 service token。

响应中的 `client_secret` 会加密保存；平台管理员可在租户管理的「接入信息」中随时查看并复制，也可重新生成。普通项目应省略 `administrator_user_id`，只配置 `member` 映射并把 `max_role` 设置为 `member`。

已有 client 升级后可由平台管理员补绑或更换管理员：

```http
PUT /api/v1/admin/integration-clients/<client_id>/administrator
Authorization: Bearer <平台管理员令牌>
Content-Type: application/json

{"user_id":"<已有租户管理员用户ID>"}
```

### 2.3 用户映射规则

外部身份唯一键为：

```text
client_id + external_tenant_id + external_user_id
```

- 普通用户首次访问时，在 client 绑定租户下自动创建 `member`，映射保存到 `integration_external_identities`。
- 同一外部用户编号从两个 client 进入时产生两份隔离映射，不会串项目。
- 外部管理员只映射到 client 显式绑定的现有租户管理员。
- 已建立映射不会因为角色参数变化而静默改绑到另一个内部账号。

## 3. 宿主后端认证

### 3.1 获取 service token

```http
POST /api/integration/v1/auth/token
Content-Type: application/json

{
  "client_id": "erp-project-a",
  "client_secret": "<仅后端保存>"
}
```

### 3.2 为当前用户申请 ticket

业务系统后端必须从自己的登录态读取用户身份，禁止直接信任浏览器传来的用户 ID 或角色。

```http
POST /api/integration/v1/auth/bootstrap
Authorization: Bearer <service_token>
Content-Type: application/json

{
  "external_tenant_id": "project-a",
  "external_user_id": "user-9527",
  "external_roles": ["project_user"],
  "active": true,
  "origin": "https://weknora.example.com"
}
```

Node.js 宿主后端示例：

```js
app.post('/host/weknora-ticket', requireLogin, async (req, res) => {
  const serviceToken = await getCachedFinOpsSysServiceToken()
  const response = await fetch(`${WEKNORA_URL}/api/integration/v1/auth/bootstrap`, {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${serviceToken}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      external_tenant_id: req.user.projectId,
      external_user_id: req.user.id,
      external_roles: req.user.isProjectAdmin ? ['project_admin'] : ['project_user'],
      active: req.user.active,
      // 必须等于浏览器加载 FinOpsSys 前端时的页面 Origin（与 WEKNORA_FRONTEND_URL 的 origin 一致）。
      // 跨域直连：独立 FinOpsSys Origin；同域反代：宿主 Origin。
      origin: new URL(WEKNORA_FRONTEND_URL).origin,
    }),
  })
  const result = await response.json()
  res.status(response.status).json(result)
})
```

## 4. 左侧菜单嵌入知识库

宿主菜单点击“知识库”后，加载 `WEKNORA_FRONTEND_URL` 下的嵌入路径。跨域直连时该 URL 指向独立 FinOpsSys；同域反代时指向宿主自身（由网关转发到 FinOpsSys）。

独立 FinOpsSys 前端必须在 `FRAME_ANCESTORS` 中明确允许宿主 Origin，否则浏览器会拦截 iframe。值采用 CSP source-list 格式，只填写 Origin，不带路径；多个宿主用空格分隔。未配置时默认为仅允许同源（`'self'`）。

**推荐写法（跨域或同域反代需要显式白名单时）：** 在 `docker-compose.override.yml` 中设置。仓库示例：

| 场景 | 示例文件 |
| --- | --- |
| 仅配置 `FRAME_ANCESTORS`（跨域直连） | [`docker-compose.embed.override.example.yml`](../deploy/examples/bidder-integration/docker-compose.embed.override.example.yml) |
| 与 bidder-agent 同机 Docker（网络 + 别名 + CSP） | [`docker-compose.bidder-integration.override.example.yml`](../deploy/examples/bidder-integration/docker-compose.bidder-integration.override.example.yml) |

同域反代 + bidder-agent 时优先使用后者；`external-weknora` 别名必须与宿主 `WEKNORA_INTEGRATION_BASE_URL` 主机名一致（**勿写成 `external-wennora`**）。

```yaml
# docker-compose.override.yml 片段（完整示例见上表 bidder-integration 文件）
services:
  frontend:
    environment:
      FRAME_ANCESTORS: "'self' https://project-a.example.com"
```

同域反代且父子页面 Origin 完全一致时，可只保留 `'self'`：

```yaml
      FRAME_ANCESTORS: "'self'"
```

> **注意：** 不推荐仅在 `.env` 中写带空格的值。
>
> Docker Compose 读取 `.env` 时可能截断，例如 `FRAME_ANCESTORS='self' https://project-a.example.com` 实际只会得到 `self`。此时 nginx 会输出无效的 `frame-ancestors self`，iframe 表现为空白且控制台报 CSP 错误。

```env
# 不推荐：含空格时易被截断
# FRAME_ANCESTORS='self' https://project-a.example.com
```

修改后执行 `docker compose config | grep FRAME_ANCESTORS`，确认解析结果包含带引号的 `'self'` 与完整宿主 Origin，再重启 frontend 容器。也可用下列命令检查线上响应头（将 URL 换成实际嵌入页）：

```bash
curl -sI 'https://project-a.example.com/knowledge/embed/platform/knowledge-bases' | grep -i content-security-policy
# 期望：frame-ancestors 'self' https://project-a.example.com
```

不要配置为 `*`。确认嵌入页响应的 `Content-Security-Policy` 的 `frame-ancestors` 包含宿主 Origin，且宿主网关没有额外叠加 `frame-ancestors 'none'`。

跨域直连示例：

```html
<iframe
  id="knowledge-frame"
  src="https://weknora.example.com/knowledge/embed/platform/knowledge-bases?mode=embedded-page&parent_origin=https%3A%2F%2Fproject-a.example.com"
  title="知识库管理"
  referrerpolicy="strict-origin"
  sandbox="allow-scripts allow-same-origin allow-forms allow-downloads allow-modals allow-popups allow-popups-to-escape-sandbox"
  allow="clipboard-write; microphone">
</iframe>
```

同域反代时把 `src` 换成宿主 Origin，例如 `https://project-a.example.com/knowledge/embed/platform/knowledge-bases?...`，`parent_origin` 仍为宿主 Origin。

`sandbox` / `allow` 缺省会导致“点了没反应”，请按能力补齐（官方 Widget SDK 已按下列声明创建 iframe；自建管理页 iframe 须自行声明）：

| 声明 | 作用 | 缺失时的典型现象 |
| --- | --- | --- |
| `allow-scripts` / `allow-same-origin` | 运行嵌入页并读写 Cookie / `sessionStorage` | 页面空白或无法登录 |
| `allow-forms` | 表单与文件选择上传 | 上传/表单无响应 |
| `allow-downloads` | `<a download>` 与文件下载 | 文档/示例下载失败 |
| `allow-modals` | 原生 `confirm`/`alert`（纵深防御；FinOpsSys 内删除已改用应用内弹窗） | 控制台 `Ignored call to 'confirm()'`，文件夹删除等无反应 |
| `allow-popups` | `window.open`、`target=_blank` | 外链、FAQ 失败条目下载、网页引用点击无反应 |
| `allow-popups-to-escape-sandbox` | 弹出窗口不受父 iframe 沙箱限制 | 外链能开窗但仍被沙箱限制 |
| `allow="clipboard-write"` | 剪贴板写入 | 复制引用/内容失败 |
| `allow="microphone"` | 语音输入 | 麦克风权限被拒 |

注意：`allow-scripts` + `allow-same-origin` 同时存在时，sandbox 不能再当作父子页面之间的安全边界；Origin / ticket / CSRF 仍是主防线。

握手流程：

1. iframe 发出 `{version: 1, type: "ready"}`（`targetOrigin` / 校验仍用约定的 FinOpsSys 前端 Origin，同域时即宿主 Origin）。
2. 宿主浏览器请求业务系统自己的 ticket BFF。
3. 宿主发送 `{version: 1, type: "auth-ready", ticket}`。
4. iframe 调用 exchange：跨域直连为 `/api/integration/v1/auth/exchange`；同域反代为 `/knowledge/api/integration/v1/auth/exchange`。成功后使用 Cookie 和/或 `session_token`（Bearer）访问后续 API。

宿主页面握手示例（须与上文 iframe `src`、`parent_origin` 使用同一组 Origin；`weknoraUrl` 等于 `WEKNORA_FRONTEND_URL`）：

```js
const weknoraUrl = 'https://weknora.example.com' // 同域反代时改为宿主 Origin
const weknoraOrigin = new URL(weknoraUrl).origin
const parentOrigin = window.location.origin
const iframe = document.getElementById('knowledge-frame')

iframe.src = `${weknoraUrl}/knowledge/embed/platform/knowledge-bases?mode=embedded-page&parent_origin=${encodeURIComponent(parentOrigin)}`

let ticketInflight = false

async function deliverTicket() {
  if (ticketInflight) return
  ticketInflight = true
  try {
    const response = await fetch('/host/weknora-ticket', {
      method: 'POST',
      credentials: 'include',
    })
    const result = await response.json()
    if (!response.ok) throw new Error(result.message || '申请 ticket 失败')
    const ticket = result.data?.ticket ?? result.ticket
    iframe.contentWindow?.postMessage({ version: 1, type: 'auth-ready', ticket }, weknoraOrigin)
  } catch (error) {
    ticketInflight = false
    console.error('FinOpsSys 嵌入认证失败', error)
  }
}

window.addEventListener('message', (event) => {
  if (event.origin !== weknoraOrigin || event.source !== iframe.contentWindow) return
  const message = event.data
  if (!message || message.version !== 1) return
  if (message.type === 'ready') void deliverTicket()
  if (message.type === 'unauthorized') {
    ticketInflight = false
    void deliverTicket()
  }
})
```

`/host/weknora-ticket` 为宿主自己的 BFF，内部调用 §3.2 bootstrap 并把 `ticket` 返回浏览器；不要把 `client_secret` 或 service token 下发到前端。

外部角色映射为 `tenant_admin` 且 client 同时拥有 `knowledge:write` 时，嵌入页会显示以下管理入口：

- 新建知识库；
- 知识库设置；
- 文件上传；
- 文件夹管理。

管理操作仍由 FinOpsSys 原生接口完成；同域反代下浏览器走 `/knowledge/api/...` 与 `/knowledge/files`。普通 `member` 或缺少 `knowledge:write` scope 时，这些入口不会显示。

如果 client 使用 `selected` 并配置固定 `knowledge_base_ids`，需要注意：

- 新建知识库后，平台管理员还必须把新 ID 加入该 client 的 allowlist；
- 浏览器必须重新申请 ticket，当前 Integration 会话不会自动扩大授权范围；
- 需要管理员在页面内持续创建和管理任意新知识库的项目，应使用 `knowledge_base_access_mode: "all"`；
- `tenant_admin` 只提供租户管理角色，不能绕过 Client 的租户边界或所选访问模式。

```http
PUT /api/v1/admin/integration-clients/<client_id>/knowledge-bases
Authorization: Bearer <平台管理员令牌>
Content-Type: application/json

{"knowledge_base_ids":["<原知识库ID>","<新知识库ID>"]}
```

更新 allowlist 会撤销该 client 的现有会话，宿主应重新申请 service token 和 ticket。

打开指定知识库或文档：

```text
/knowledge/embed/platform/knowledge-bases/<knowledge_base_id>
  ?mode=embedded-page
  &knowledge_id=<knowledge_id>
```

生产构建：官方 `frontend` Docker 镜像会同时产出独立站（`base=/`）与嵌入站（`base=/knowledge/embed/`）。本地仅构建独立站时：

```bash
VITE_APP_BASE_PATH=/ npm run build
```

若宿主同域反代 `/knowledge/embed/`，必须使用镜像内的嵌入站产物（或自行 `VITE_APP_BASE_PATH=/knowledge/embed/ npm run build` 并按 nginx 配置放到 `/knowledge/embed/`），否则 `/assets` 会与宿主静态资源冲突。

### 4.1 同域反代网关示例

以下以 Caddy 为例。

宿主对外只暴露一个 Origin 时，由网关把 FinOpsSys 嵌入路径转发到内网 frontend（示例内网地址 `192.168.1.10:8089`，按实际部署替换）。**不要**让浏览器直接访问内网 FinOpsSys 端口，否则可能触发 Private Network Access 拦截。

```caddyfile
:443 {
	# 宿主自有 SPA / API 按现有规则处理 ...

	# FinOpsSys Widget 静态资源
	handle /widget/* {
		reverse_proxy 192.168.1.10:8089
	}

	# FinOpsSys 嵌入站（页面、/knowledge/embed/assets、/knowledge/api、/knowledge/files）
	handle /knowledge/* {
		reverse_proxy 192.168.1.10:8089
	}
}
```

要点：

- 仅反代 `/widget/*` 与 `/knowledge/*` 到 FinOpsSys frontend；FinOpsSys App API 由 frontend nginx 的 `/knowledge/api/`、`/knowledge/files` 再转到 App，避免与宿主自有 `/api/*` 冲突。
- 宿主全局 CSP 若包含 `frame-ancestors 'none'`，须对 `/widget/*`、`/knowledge/*` **排除**该规则（见 §1.1、§9）。
- 反代 SSE 时关闭缓冲（Caddy 默认通常可流式转发；Nginx 需 `proxy_buffering off`）。

跨域直连时，同一 FinOpsSys 前端 Origin 至少能访问 `/api/*`、`/files`、`/assets/*` 和 `/widget/*`；SSE 须关闭代理缓冲。同域反代时由宿主转发 `/widget/*`、`/knowledge/*`，业务后端仍只做 ticket BFF，服务端 Integration 调用走内网 App 地址即可。

## 5. 悬浮聊天框

从 `WEKNORA_FRONTEND_URL` 加载 `/widget/weknora-widget.iife.js` 后初始化（跨域直连为独立 FinOpsSys；同域反代为宿主同源路径）：

```js
const weknoraUrl = 'https://weknora.example.com' // 同域反代时改为宿主 Origin，如 https://project-a.example.com
const weknoraOrigin = new URL(weknoraUrl).origin
const parentOrigin = window.location.origin
const widget = WeKnoraWidget.initWidget({
  version: 1,
  instanceId: 'project-a-knowledge-chat',
  iframeUrl: `${weknoraUrl}/knowledge/embed/embed/widget?mode=embedded-widget&parent_origin=${encodeURIComponent(parentOrigin)}`,
  targetOrigin: weknoraOrigin,
  selection: {
    mode: 'fixed',
    knowledgeBaseIds: ['<知识库ID-1>', '<知识库ID-2>'],
  },
  theme: { title: '项目 A · 知识助手', primaryColor: '#0052d9' },
  preserveSession: true,
})

widget.on('ready', async () => {
  const response = await fetch('/host/weknora-ticket', { method: 'POST' })
  const result = await response.json()
  widget.authenticate(result.data.ticket)
})

widget.on('unauthorized', () => {
  // 重新申请 ticket；不要复用旧 ticket。
})

widget.on('open-document', ({ knowledgeBaseId, knowledgeId }) => {
  openKnowledgeMenu({ knowledgeBaseId, knowledgeId })
  widget.close()
})
```

选库模式：

| 模式 | 用途 |
| --- | --- |
| `fixed` | 固定使用指定知识库，至少传一个 ID |
| `selectable` | 用户可在 client allowlist 内选择知识库 |
| `all-allowed` | 使用该用户最终获准的全部知识库 |

SDK 方法包括 `open()`、`close()`、`destroy()`、`moveTo()`、`resizeTo()`、`maximize()`、`restore()` 和 `resetLayout()`；事件包括 `ready`、`unauthorized`、`answer-completed`、`open-document` 和 `error`。

Widget 内含语音输入时，SDK 创建的 iframe 会声明：

- `allow="microphone; clipboard-write"`；
- 与管理页相同的 `sandbox`，包含 `allow-modals`、`allow-popups`、`allow-popups-to-escape-sandbox`。

宿主站点还需允许浏览器使用麦克风。如果部署层配置了 `Permissions-Policy`，必须为独立 FinOpsSys Origin（同域反代则为宿主 Origin）开放：

- `microphone`；
- 需要时开放 `clipboard-write`。

语音识别使用 Integration 会话接口，不应把外挂会话 ID 发送到普通 `/api/v1/sessions/*` 语音接口。

### 6.1 认证接口参数

除特别说明外，路径中的 `:knowledge_base_id`、`:session_id` 和 `:message_id` 均为路径参数；JSON 接口使用 `Content-Type: application/json`。下列说明覆盖上方 Integration API 清单中的每个方法；没有请求体或查询参数的接口也会明确标注。

`POST /auth/token`：

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `client_id` | JSON body | 是 | Integration Client ID |
| `client_secret` | JSON body | 是 | Integration Client 密钥，只能由服务端发送，不能下发浏览器 |

`POST /auth/bootstrap`：

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `Authorization` | request header | 是 | `Bearer <service_token>`；使用 `/auth/token` 获取的 service token |
| `external_tenant_id` | JSON body | 是 | 业务系统中的租户、项目或工作区 ID，用于身份映射 |
| `external_user_id` | JSON body | 是 | 业务系统中的用户 ID，用于身份映射 |
| `external_roles` | JSON body | 否 | 业务系统角色数组，用于映射 FinOpsSys 用户角色 |
| `active` | JSON body | 否 | 用户是否有效；不传时由服务端按默认状态处理 |
| `origin` | JSON body | 是 | 浏览器实际加载 FinOpsSys 前端的页面 Origin，必须与 client 允许的 Origin 一致 |

`POST /auth/exchange`：

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `ticket` | JSON body | 是 | `/auth/bootstrap` 返回的一次性 ticket |
| `Origin` | request header | 是（浏览器场景） | 浏览器实际页面 Origin；服务端据此校验 ticket 并绑定会话 |

`POST /auth/refresh`：

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `Authorization` | request header | 与 Cookie 二选一 | `Bearer <session_token>`；跨站嵌入优先使用此方式 |
| `weknora_integration_session` | Cookie | 与 Authorization 二选一 | `/auth/exchange` 设置的浏览器会话 Cookie |
| `Origin` | request header | 是（浏览器场景） | 必须是会话绑定的浏览器 Origin |
| `X-CSRF-Token` | request header | 是 | `/auth/exchange` 或上一次 refresh 返回的 CSRF token |

该接口没有请求体。`POST /auth/logout` 使用同样的会话、`Origin` 和 `X-CSRF-Token` 参数；没有请求体。存在浏览器会话时必须提供认证和 CSRF 参数，注销后会清除会话 Cookie。

> **通用认证规则**
>
> 除认证接口外，以下受保护 Integration 接口均需要 `Authorization: Bearer <service_token_or_session_token>`，或使用 `/auth/exchange` 设置的浏览器会话 Cookie。
>
> - 浏览器会话调用非 `GET` 接口时，还必须带 `Origin` 和 `X-CSRF-Token`；
> - 服务端使用 service token 时不能带浏览器 `Origin`。

| 参数 | 必填 | 说明 |

`folder_ids` 的展开、`filter_disabled_folders` 的过滤、`knowledge_ids` 与文件夹范围的校验规则，以本节后面的检索说明为准；批量接口允许每个 query 独立设置这些参数。

| `after_event_id` | query | 否 | 从指定事件 ID 之后读取；未传时使用 `Last-Event-ID` |
| `Last-Event-ID` | request header | 否 | SSE 客户端自动发送的断点事件 ID |

该接口返回 `text/event-stream`；事件游标过期时返回 `410`，调用方应改用消息快照接口。

`POST /chat/sessions/:session_id/messages/:message_id/cancel`：`session_id` 和 `message_id` 是必填路径参数；没有查询参数或请求体，取消尚未完成的回答。

`POST /chat/sessions/:session_id/voice/tts`：

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `session_id` | path | 是 | 会话 ID |
| `message_id` | JSON body | 是 | 已完成的 assistant 消息 ID |
| `model_id` | JSON body | 是 | TTS 模型 ID |
| `language` | JSON body | 否 | 语言提示，具体支持范围由 TTS 模型决定 |
| `voice` | JSON body | 否 | 音色，具体支持范围由 TTS 模型决定 |
| `speed` | JSON body | 否 | 语速，范围 `0–4`；不传使用模型默认值 |
| `format` | JSON body | 否 | 输出格式：`mp3`、`wav`、`opus` 或 `pcm`，默认 `mp3` |

接口返回音频流，不返回 JSON。

`POST /chat/sessions/:session_id/voice/asr`：

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `session_id` | path | 是 | 会话 ID |
| `model_id` | multipart form | 是 | ASR 模型 ID |
| `audio` | multipart form | 是 | 录音文件，非空且最大 25 MiB |

请求使用 `multipart/form-data`，成功返回识别文本和时间片段。

### 6.6 上传单个文档

`POST /api/integration/v1/knowledge-bases/:knowledge_base_id/knowledge/file` 使用 `multipart/form-data` 上传单个文档，成功返回 `201`。请求必须携带 `knowledge:write` scope，并且目标知识库在当前主体的最终授权范围内。

```bash
curl --request POST 'https://weknora.example.com/api/integration/v1/knowledge-bases/<knowledge_base_id>/knowledge/file' \
  --header 'Authorization: Bearer <service_token_or_session_token>' \
  --form 'file=@./docs/guide.pdf' \
  --form 'fileName=guide.pdf' \
  --form 'metadata={"source":"erp","external_id":"doc-001"}'
```

表单字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | 非空文件 |
| `fileName` | 否 | 自定义文档名称，长度不超过 500；不是文件夹路径参数 |
| `metadata` | 否 | JSON 字符串，内容必须是 `string` 到 `string` 的对象，长度不超过 64 KiB |

上传约束：

- 当前 Integration 上传接口不读取 `tag_id` 和 `enable_multimodel`，不能通过该接口指定目标文件夹或强制覆盖多模态配置；
- 未指定文件夹时，文档归入默认的“未分类”位置；
- FAQ 知识库和视频文件不支持此上传接口；
- 全局 `MAX_FILE_SIZE_MB` 默认上限为 2047 MB；
- Integration 的 `INTEGRATION_MAX_REQUEST_BYTES` 未设置时会跟随该上限，默认约为 2047 MiB；若显式配置了更小值，则以该值为准；
- 还需确认上游 Nginx 的 `client_max_body_size` 已配置为 2047M，实际文件还需预留 multipart 请求开销。

响应的 `data` 是创建后的知识元数据，通常会先处于 `pending`（治理知识库可能为 `draft`）状态，解析、切块和向量化由后台异步完成；调用方应保存返回的 `data.id`，再通过知识列表或下文的分块查询接口确认处理结果。

### 6.7 批量上传文件

当前没有 `/knowledge-bases/:knowledge_base_id/knowledge/batch` 之类的专用 Integration 批量上传端点。批量上传的稳定做法是由调用方枚举文件，并对每个文件独立调用 6.6 的单文件接口：

```bash
find ./docs -maxdepth 1 -type f -print0 | while IFS= read -r -d '' file; do
  curl --fail-with-body --request POST \
    'https://weknora.example.com/api/integration/v1/knowledge-bases/<knowledge_base_id>/knowledge/file' \
    --header 'Authorization: Bearer <service_token>' \
    --form "file=@${file}"
done
```

这些请求没有事务语义：某个文件失败不会回滚其他文件。调用方应按文件记录成功/失败和返回的知识 ID，只重试失败项，并控制并发以避免触发单请求限流。

### 6.8 文件夹上传

当前没有专用的 `/folder` Integration 端点。文件夹上传需要递归枚举文件后逐文件调用 6.6，并注意：

- Integration API 不会自动保留本地目录层级；
- 不能通过 `tag_id` 把文件绑定到指定知识库文件夹。

如果必须使用嵌入式管理页面的文件夹选择和文件夹归档能力，应调用嵌入会话可复用的原生文件接口，而不是把它当作后端 Integration 契约：

```text
同域反代：/knowledge/api/v1/knowledge-bases/<knowledge_base_id>/knowledge/file
跨域直连：https://weknora.example.com/api/v1/knowledge-bases/<knowledge_base_id>/knowledge/file
```

原生文件接口支持 `file`、`fileName`、`metadata`、`enable_multimodel` 和 `tag_id`。

> **调用注意：** 修改请求需要嵌入会话 Cookie 或 `session_token`，以及 exchange 返回的 `X-CSRF-Token`。纯后端服务不能使用 service token 直接把这个原生接口当作 Integration API 调用。

原生文件接口的参数：

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `knowledge_base_id` | path | 是 | 目标知识库 ID |
| `file` | multipart form | 是 | 要上传的非空文件 |
| `fileName` | multipart form | 否 | 自定义文件名；文件夹上传时可传相对路径以保留目录层级 |
| `metadata` | multipart form | 否 | JSON 格式的字符串键值元数据 |
| `enable_multimodel` | multipart form | 否 | 是否启用多模态处理，布尔值 |
| `tag_id` | multipart form | 否 | 目标文件夹/标签 ID；使用文件夹列表接口返回的 ID |

### 6.9 查询文档分块

当前 Integration 路由尚未提供 `/api/integration/v1/chunks`。嵌入页面在已有用户/租户/知识库授权下，可以复用原生只读接口查询分块；同域反代和跨域直连路径分别为：

```text
GET /knowledge/api/v1/chunks/<knowledge_id>?page=1&page_size=20
GET https://weknora.example.com/api/v1/chunks/<knowledge_id>?page=1&page_size=20
```

分块列表接口参数：

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `knowledge_id` | path | 是 | 要查询分块的知识/文件 ID |
| `page` | query | 否 | 页码，默认 `1` |
| `page_size` | query | 否 | 每页数量，默认 `10`，最大 `100` |

按分块 ID 查询接口 `GET /api/v1/chunks/by-id/<chunk_id>` 的参数如下：

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `chunk_id` | path | 是 | 要查询的分块 ID；不需要再传 `knowledge_id` |

接口只返回文本分块，并会对 `content` 做展示安全清理；请求仍受当前用户和知识库查看权限约束，`GET` 请求不需要 CSRF token。

```json
{
  "success": true,
  "data": [
    {
      "id": "<chunk_id>",
      "knowledge_id": "<knowledge_id>",
      "knowledge_base_id": "<knowledge_base_id>",
      "content": "分块正文",
      "chunk_index": 0,
      "is_enabled": true,
      "chunk_type": "text"
    }
  ],
  "total": 5,
  "page": 1,
  "page_size": 20
}
```

按分块 ID 查询单条分块时，使用 `GET /api/v1/chunks/by-id/<chunk_id>`（同域反代前缀为 `/knowledge/api/v1`）。该接口同样不是后端 service token 的 Integration 稳定端点；如需服务端直接查询分块，需要另行实现并注册对应 Integration API。

### 6.10 检索、文件夹与调用约束

#### 文件夹列表行为

文件夹接口的 `knowledge_base_ids` 可省略，规则如下：

- 省略、传空值或传 `null` 时，服务端返回当前主体最终获准的全部知识库文件夹；
- 显式传入逗号分隔的 ID 列表时，任一知识库不存在或不可访问都会统一返回 `404`；
- 每个文件夹项包含 `knowledge_base_id`、`id`、`name`、`parent_id` 和 `sort_order`；
- 虚拟“公共知识”项应直接使用接口响应中的 `id`，不要依赖其内部生成格式。

#### 表格分析依赖

XLS 需要运行 FinOpsSys App 的主机或自定义镜像安装 LibreOffice，并确保 `soffice` 位于 `PATH`；官方 App 镜像已包含该依赖。非容器部署可用 `soffice --version` 检查，缺少依赖时 XLS 分析会返回 `table_load_failed`，CSV/XLSX 不受影响。

#### 浏览器修改请求

修改类浏览器请求必须携带 exchange 返回的 `X-CSRF-Token`；创建消息还必须提供唯一的 `Idempotency-Key`。跨站场景优先使用 Bearer `session_token`。

#### 检索范围

检索范围规则如下：

- `/rag/search` 可选传 `folder_ids`；批量接口则在每个 query 中独立传入；
- `folder_ids` 缺失、为 `null` 或为空数组时，表示搜索本次 `knowledge_base_ids` 的完整范围；
- `folder_ids` 非空时，普通文件夹 ID 展开为自身及其全部子文件夹；
- 列表接口返回的虚拟“公共知识”ID 展开为所属知识库的全部公共子文件夹；
- 普通文件夹不再自动带上公共知识，只传虚拟“公共知识”ID 时只搜索公共知识；
- 如果同时传 `knowledge_ids`，它只会把检索范围收窄到指定文件，不等同于全文读取；
- 每个指定文件也必须属于最终文件夹范围，否则返回 `invalid_knowledge_folder_scope`。

#### 文件夹搜索开关

`POST /knowledge-bases/:knowledge_base_id/knowledge/search` 的文件夹筛选规则如下：

- 接受 JSON 字段 `folder_ids` 和 `filter_disabled_folders`；
- 文件夹范围及虚拟“公共知识”ID 的展开规则与 RAG 一致；两项同时使用时取交集；
- `folder_ids` 缺失或为空数组时，不按显式文件夹筛选；
- `filter_disabled_folders` 缺失或为 `false` 时，不检查文件夹搜索开关；
- 原 GET 接口保持无筛选的完整列表行为。

单次请求和批量接口的每个 query 均可传 `filter_disabled_folders`：

- 字段缺失或为 `false` 时，不检查文件夹“搜索”开关；
- 为 `true` 时，排除关闭搜索的文件夹及其全部子文件夹中的文件；
- 它不会扩大 `knowledge_base_ids` 范围；
- 与 `folder_ids` 同时使用时取两者交集；
- 合法文件夹因搜索开关被排除时返回空结果，而不是 `invalid_folder_ids`；
- 批量接口可让不同 query 分别选择是否过滤。

#### 返回数量

`/rag/search` 和批量接口的每个 query 可选传 `top_k`：

- 省略或为 `0` 时，使用平台“检索策略”中的最终结果数；
- 正值只能缩小返回数量，实际返回上限为 `min(top_k, 平台 Rerank Top K)`；
- 该参数不会改变向量/关键词召回、RRF 融合或送入 rerank 的候选预算。

#### 批量结果预算与去重

`/rag/search-batch` 的整批预算规则如下：

- 受平台“检索策略”中的“批量检索总结果上限”和“批量检索正文字符上限”约束；
- 缺省值分别为 `200` 和 `200000`，由平台管理员统一配置，Integration 调用方不能覆盖；
- 各 query 完成既有 Rerank Top K 截断后，系统按请求顺序轮询分配整批预算；
- 响应仍保持逐 query 分组和原请求顺序。

请求顶层可选传 `preserve_duplicates`，相关规则如下：

- 省略或为 `false` 时，对跨查询证据去重；为 `true` 时，保留重复证据；
- 去重键优先使用 `knowledge_version_id + chunk_id`；缺少 `knowledge_version_id` 时回退到 `knowledge_id + chunk_id`；
- 缺少 `chunk_id` 时不去重；
- 两个整批上限始终是硬限制，即使保留重复证据，每份结果也会分别占用条数和正文字符预算；
- 预算不足或证据已由其他 query 保留时，某个状态为 `completed` 的 query 可能返回空 `results`；
- 字符预算按 Unicode 字符计算，不截断单条证据正文。

#### 版本与缓存

搜索结果会返回 `knowledge_version_id`。启用知识治理时，只有当前生效、可检索且未失效版本的结果会进入排序和响应；草稿、待审核、未发布、过期或与当前版本不一致的结果不会作为引用返回。调用方如需缓存证据，应至少使用 `knowledge_version_id + chunk_id` 作为稳定身份。

## 7. 接入 bidder-agent 时的边界

bidder-agent 只保留业务系统用户、项目权限和 ticket BFF；知识库内容、文档、索引、向量检索、知识库管理页面和悬浮聊天均由独立 FinOpsSys 提供。

- bidder-agent 后端需要查询知识库时，调用 `/api/integration/v1/rag/search` 或 chat API，不能再查本地 FinOpsSys 表或本地 FinOpsSys 内容接口。
- bidder-agent 本地只保存 `provider_kb_id` 等映射元数据，用于业务记录关联，不是知识库事实来源。
- 外挂启用后，bidder-agent 不启动本地 FinOpsSys PostgreSQL、Redis、docreader、App 或 UI，也不显示本地知识库管理入口。
- `client_secret` 只放 bidder-agent 后端环境变量；前端只拿到 `WEKNORA_FRONTEND_URL` 和一次性 ticket。
- **跨域直连**：`WEKNORA_FRONTEND_URL` 填独立 FinOpsSys 前端；`allowed_origins` / bootstrap `origin` 填该前端 Origin；`WEKNORA_INTEGRATION_ORIGIN` 填宿主 Origin（`parent_origin`）。
- **同域反代**（如公司公网入口反代 `/widget`、`/knowledge`）：
  - `WEKNORA_FRONTEND_URL` 与 `WEKNORA_INTEGRATION_ORIGIN` 同为宿主 Origin；
  - `allowed_origins` 填宿主 Origin；
  - 禁止让浏览器去拉内网 FinOpsSys 地址；
  - `FRAME_ANCESTORS` 仍建议通过 `docker-compose.override.yml` 显式配置（见 §4）。

### 7.2 宿主角色变化

Integration external identity 以 `(client_id, external_tenant_id, external_user_id)` 为稳定身份。

宿主用户在 `member` 与 `tenant_admin` 之间变化时，继续提交当前权威角色。服务端会在 bootstrap 事务内对账身份绑定并撤销旧主体的活动会话，不需要删除身份、轮换 secret 或把管理员降级为 member。

需要晋升管理员但 Client 的 `administrator_user_id` 缺失、跨租户、停用或已不是租户管理员时，接口返回 `403 administrator_binding_invalid`。该错误表示管理员绑定配置异常，不表示 `client_secret` 失效。

## 8. 用户停用和重新启用

用户被移出业务项目或离职时，宿主后端调用 bootstrap 并传 `active: false`。接口返回拒绝是预期结果，同时服务端会：

1. 将该 client 下的外部身份标记为停用；
2. 撤销该 client 与该用户组合下的现有浏览器会话；
3. 拒绝后续 ticket。

重新加入项目时传 `active: true`。系统只恢复项目身份；如果内部用户、client、租户或知识库权限已停用，仍会拒绝访问。停用一个 client 的身份不会影响其他项目，也不会停用显式绑定的租户管理员账号本身。

## 9. 权限与安全检查清单

- 每个项目使用独立 client，不共享 `client_secret`。
- `allowed_origins` 使用精确 Origin，不使用 `*`；取值等于浏览器加载 FinOpsSys 前端时的页面 Origin（跨域直连=FinOpsSys Origin，同域反代=宿主 Origin）。
- 公网页不要引用内网 FinOpsSys 地址，避免 Private Network Access 拦截。
- 同域反代时宿主 CSP 勿对 `/widget`、`/knowledge` 叠加 `frame-ancestors 'none'`。
- 跨域或同域反代部署后，用 `docker compose config` 与 `curl -sI` 确认 `frame-ancestors` 含 `'self'` 与宿主 Origin（见 §4）。
- 普通项目设置 `max_role: member`。
- 管理员项目显式填写 `administrator_user_id`。
- 需要新建、设置或上传文档的管理员项目授予 `knowledge:write`，并确认外部管理员角色映射为 `tenant_admin`。
- 需要管理租户全部知识库时使用 `knowledge_base_access_mode: all` 且保持 `knowledge_base_ids` 为空；只开放部分知识库时使用 `selected` 并列出允许的 ID。
- 后端从自身会话读取外部用户和角色，不接受浏览器冒充。
- ticket 不放 URL、不缓存、不重放。
- 收到 `unauthorized` 后重新申请 ticket。
- 用户退出或停用时同步状态并销毁 Widget。
- 定期轮换 secret；结束后调用 `/api/v1/admin/integration-clients/:client_id/revoke-previous-secret`。
- 自建管理页 iframe 的 `sandbox`/`allow` 至少包含上文第 4 节表格中的声明；缺 `allow-modals` / `allow-popups` 时会出现删除、外链“点了没反应”。

### 9.1 常见状态码

| 状态码 | 含义 |
| --- | --- |
| `400` | 参数非法 |
| `401` | 凭证或会话失效 |
| `403` | Origin、角色、租户或知识库越权 |
| `409` | ticket 重放或幂等冲突 |
| `410` | SSE 游标过期 |
| `429` | 超过限流 |

### 9.2 浏览器控制台与 iframe 故障排查

浏览器控制台与 iframe 相关的常见提示：

悬浮 Widget 使用受限的 Integration browser session，只调用 `/api/integration/v1` 对话接口。

站内聊天的传统推荐问题接口 `/api/v1/agents/:id/suggested-questions` 不属于 Widget 权限范围。Widget 默认关闭推荐问题加载，避免为非必要展示扩大嵌入会话权限。

| 控制台提示 / 现象 | 处理 |
| --- | --- |
| `Framing '...' violates ... frame-ancestors 'self'` 或 `frame-ancestors self` | 检查 `FRAME_ANCESTORS` 是否被 Docker Compose 截断；用 `docker compose config` 与 `curl -sI` 确认 CSP 含 `'self'` 与宿主 Origin（见 §4） |
| iframe 空白、无 CSP 报错，控制台长时间无 `auth-ready` | 确认宿主监听 iframe 的 `ready` 并回传 `{type:"auth-ready", ticket}`；直接打开嵌入 URL 不会自动登录 |
| 嵌入页静态资源 404（`/assets/*` 而非 `/knowledge/embed/assets/*`） | iframe `src` 必须使用 `/knowledge/embed/...`，不要用 `/knowledge/platform/...` 或根路径 `/` |
| 页面显示「拒绝连接」/ 网关无响应 | 检查宿主反代（如 Caddy）与 FinOpsSys frontend 容器是否运行 |
| `bootstrap` 409、「认证服务暂不可用」 | 检查 `external-weknora` 别名与 `WEKNORA_INTEGRATION_BASE_URL`；见 §7.1 示例与自检 |
| `Ignored call to 'confirm()'. ... 'allow-modals' is not set` | 给 iframe 增加 `allow-modals`；并升级到已用应用内确认框的 FinOpsSys 前端 |
| 外链 / FAQ 失败下载无反应 | 增加 `allow-popups` 与 `allow-popups-to-escape-sandbox` |
| 复制按钮无效 | `allow="clipboard-write"`，必要时调整宿主 `Permissions-Policy` |
| 语音按钮无效 | `allow="microphone"` + 宿主 `Permissions-Policy` 放行麦克风 |
| Private Network Access / 内网地址被拦 | 改用同域反代，勿让公网页直连内网 FinOpsSys |
